# Skill 版本化对照测试

用于为创作、维护或优化 Skill 的项目生成 Harness，包括单个 Skill 项目。AGENTS.md 写长期验收规则，测试输入和历史产物留在测试目录，日常调用 Skill 不加载测试历史。

## 测试集合与版本

优先使用项目已有测试目录、运行器和指标；没有则从 [测试集骨架](../assets/skill-eval-starter/README.md) 建立 `tests/evals/`。多 Skill 仓库各自隔离，可放 `skills/<name>/tests/evals/`，不要复制第二套已有测试。

| 标识 | 用途 | 规则 |
|---|---|---|
| skill_version | 被测 Skill 版本，如 v1、v2 | 对应完整快照与文件哈希；标签不是内容证据 |
| case_id + case_version | 固定输入、附件、评审标准 | 输入或标准变化升用例版本，保留旧版 |
| suite_version | 本轮选中的用例及版本列表 | 固定后不为新版结果改动；新增/替换用例升测试集版本 |
| run_id | 某次真实执行 | 每次唯一，含时间、版本和序号；重试另建记录 |

优化前保存实际工作区快照，包含 SKILL.md、references、scripts、模板及运行需要的资产，外部依赖记录版本或固定素材。未提交改动也需冻结；不要只保存主文件、用 HEAD 冒充工作区或改后重建旧版。快照不递归包含 tests/evals 的历史与自身副本。每份文件记录 SHA-256，运行前校验，已归档记录不得覆盖。

## 比较范围：最近相邻两版

每次只比较最近相邻两版：修改前最近一版 baseline 与修改后最新版 candidate，例如 v2→v3，下一轮 v3→v4。更早版本仅归档，不参与本轮比较；最近前版缺失时报告无法对照，不用更早版本顶替。

- baseline＝修改前最近一版的实际完整快照；candidate＝修改后最新版。首次创建没有 baseline，记录首次基线；已有 Skill 的最近前版缺失与首次创建分别报告。
- 以版本继承关系确定这两版，不按文件修改时间或运行 ID 猜测。清单记录 candidate 的直接前版 baseline；本轮 candidate 成为下一轮 baseline。
- 两版使用相同固定输入、标准与可比配置。历史输出哈希和配置均匹配时可以复用；不匹配或没有对应输出时，仅用窗口内的历史快照补跑。快照缺失则标记缺口，不用更早版本顶替。
- 报告并列 baseline/candidate 证据，说明本轮变化；重试保持同一对版本，只增加运行 ID。首次创建只有一版时建立首次基线；前版缺失则列未完成对照，不虚构提升。
- 除非用户明确要求，不扩展窗口。历史失败输入可以继续作为固定用例，但被测 Skill 版本只取这个窗口。

## 固定用例与运行

- 优化前明确本次改动目标、硬性失败条件与质量标尺。测试集至少含核心常规输入、本次改动针对的输入；适用时加入边界/缺失信息、历史失败、非触发输入。创作类评内容证据与可用性，工具类评真实结果与边界行为，不能一律用文风或字数打分。
- 每次至少运行本次影响用例和一项核心回归；影响整个流程时覆盖全部核心用例。其余列为未运行并说明原因，不算通过。新建 Skill 没有旧版时运行首次基线，明确不可宣称前后提升。
- 两版使用同一输入与素材哈希、模型与配置、工具环境和输出要求，在独立上下文生成；每端只读自身快照和输入，不读其他版本产物、评审标准或预期答案。评审另行读取标准与结果。
- 记录实际模型标识、推理配置、可控采样参数、依赖版本和环境。不可固定的参数标记 unknown；配置不一致或关键环境不可核对时，标为不可严格比较，不能声称是 Skill 带来的改善。
- 联网/知识库依赖优先固定检索素材，两端一致；要测真实检索时记录时间、来源和差异。运行所需的用户私有素材保留在授权存储位置，不因测试自动发布。
- 复用已存在且核实过的运行命令。没有运行器时记录实际模型调用或人工独立会话的步骤，不把假设的 `npm test`、脚本或命令写进 Harness。静态检查、手改样例、模型自报得分都不能替代真实生成。

## 对比与结论

- 原始输出原样保存，附运行状态、耗时、错误和配置；失败/超时也入库，空输出不能算通过。
- 先核验硬条件，再按同一标尺比较质量；每项引用原文位置或实际结果证据，包含改善、持平、退步、失败项。主观评分可用 0＝缺失/错误、1＝不完整、2＝完整且有证据，含义需按被测 Skill 定义。
- 评审尽量隐藏版本身份；非盲评须注明。一次采样只能描述本次差异；至少三次独立采样才讨论重复性，仍不能直接推断真实业务效果。
- 每次优化交付两版对比报告及各版原始输出链接，注明版本、用例、次数、可比性、未运行范围。硬失败不能用总分抵消，退步不能删掉。
- 应比较的版本缺少真实产出时报告“修改完成，生成验证未完成”；首次创建报告“首次基线已建立”，不能虚构优化幅度。Harness 文件本身的结构核验通过不等于目标 Skill 测试通过。

## 将新版产出加入集合

每轮新版运行产物自动追加到 `runs/` 并登记索引，包括失败输出。集合持续增加，但原始输出不自动成为正确答案。

- 新版输出默认是 `observed`（已观察），通过固定验收和人工/独立评审才登记为 `reference`（参考样例），保留评审人/方式、依据和原始运行链接；它是示例，除非任务要求精确匹配，不要求以后逐字模仿。
- 失败或退步登记为 `regression`（回归案例）；补齐可复现输入和错误断言后加入下一版测试集。失败输出不是正例。
- 本轮发现的新输入先登记候选用例，冻结输入与标准后升 suite_version；下一轮窗口内各版同跑。不能只测最新版再混入本轮成绩，也不能根据新版输出反向修改本轮标准。
- 索引至少列 Skill 版本、用例版本、运行 ID、状态、样例类别、报告与原始结果路径。历史样例废止写原因与替代关系，不删除旧证据；引用历史产物前校验版本与配置可比性。

## AGENTS.md / CLAUDE.md 规则片段

生成时替换为项目实际入口；不存在的资源先建立再引用。共享规则只维护一份，CLAUDE.md 可桥接 AGENTS.md。

```markdown
## Skill 优化验收

- 每次只比较最近相邻两版：修改前最近一版 baseline 与修改后最新版 candidate，例如 v2→v3，下一轮 v3→v4。更早版本仅归档，不参与本轮比较；最近前版缺失时报告无法对照，不用更早版本顶替。
- 修改前冻结完整 Skill 及运行依赖，记录版本和哈希；输入、附件与评审标准按用例版本固定。
- 每次优化按测试入口执行窗口内各版独立生成：同输入、同模型配置，至少覆盖本次影响用例和核心回归；新建 Skill 建首次基线。
- 每轮新版真实输出按 Skill 版本和唯一运行 ID 追加到测试集合，保留失败与退步，不覆盖旧证据。
- 输出经评审才能成为参考样例；失败补成回归用例。新增输入进入下一版测试集，两端同跑，不反向修改本轮评分标准。
- 交付对比报告：版本与配置、指标和内容证据、改善/退步/硬失败、未运行项、各版原始产物链接。无真实对照时明确“修改完成，生成验证未完成”。
```
