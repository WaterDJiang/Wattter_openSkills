# 四帧拼图：完整渲染前的用户决定

新主题仍先选制作方向。方向选定不代表批准了具体画面；完整渲染前必须展示当前工程的四张真实样帧2×2拼图，等用户明确确认这一版。

## 制作

```sh
node tools/render.cjs . --preview
# 可以按剧情选择四个不同帧号，例如：
node tools/render.cjs . --preview --review-frames 20,90,170,260
```

默认取约8%、35%、65%、92%的帧，避开空白首尾；对地图/转场等内容自行选择能判断效果的时刻。脚本输出`.preview-review/versions/v0001/contact-sheet.png`等版本文件，带帧号和时码。先完成内部画面/动作检查，再把拼图实际展示给用户。待确认时不执行`--render`。

## 有声局部试剪

锁时间轴并完成同版混音后，运行 `node tools/render.cjs . --sample-frames 240:432`。帧号按本片替换，包含起帧，止帧不含。输出在 `preview/samples/` 的新目录，独立于四帧拼图和正式回执。看片尾时从关键铺垫开始，连看最后一句和余音。完整成片走以下确认流程。

## 记录真实决定

用户看过当前拼图并明确同意后，记录当前版本和原话：

```sh
python3 tools/preview_review.py approve . --version v0001 --message '用户针对这版拼图的实际确认原话'
python3 tools/preview_review.py check . --kind pipeline
node tools/render.cjs . --render
```

上面的message是参数说明，不是可冒充用户的话。普通“继续”、风格选项A或代理自查不等于四帧确认。没有新确认就保持pending；用户要求修改时先改当前代码，再重新preview，旧批准因指纹变化失效。用户明确否定已批准版本，可执行`reject`代替`approve`，同样保存版本和原话。

同一指纹的重跑复用现有批准，无需反复询问。所有决定和旧拼图保留；不能覆盖拼图、手改清单/批准哈希绕过门禁。素材审阅仍按ASSETS.md独立执行；四帧批准不替代素材替换许可，也不替代最终MP4审阅。源码、时间轴、素材或样帧变化都须重新出图并取得当前版本确认。

完整渲染默认继承已批准的四个帧号，在候选目录重新抓取并逐张比对哈希；字体、GPU或运行环境造成样帧不同，也会在导出整片前阻断，重新预览后再交用户确认。更换候选目录但内容完全一致，可复用原批准。

## 已完成成片只换声音

画面、字幕、时序均保持时，按AUDIO-REVISION.md在独立修订目录审阅并锁定新声音，运行tools/audio_revision.py。工具校验原有效四帧批准和合成回执，复制画面流并比较所有解码帧；不重绘、不伪造新四帧确认，也不改原回执。任何画面/时序变化仍按上面的新版拼图流程。

## 已验收母片增补首帧封面

用户明确只加一帧时，按 Skill 制作契约的「封面与首帧交付」保留母片，单独生成交付版并核对封面、正文全部解码帧及一帧音轨偏移。正文画面或字幕时序调整，以及需要停留阅读的片头，按新版四帧审片。

## 地图专项

地图export使用同一个preview_review工具，但kind为map，只绑定该工程的源代码/配置/样帧；正式入片资产仍须走素材锁。地图专项命令见其README，不能以换导出器避开四帧决定。
