# 先做地点研究，再画季节明信片

适用于用户指定真实地点。目标是“一眼认出这里”，不是给通用农田/城市方块换地名。未指定具体地点时只完善方法和工程夹具，不声称已搜到某城地图。

## 网络与地图概览

- 默认auto：分别检测Google/Baidu入口，优先实际可用且响应较快的一项；用户明确偏好则优先该项。失败、超时、验证码/同意页记录原原因后换另一项，不按语言或IP猜用户网络地区。
- `python3 scripts/map_access.py --place 地名 --preferred auto`输出候选、两个位置链接与检测状态；可指定google/baidu。检测不读取密钥、不定位用户、不申请计费，只访问入口。HTTP200不能证明地图瓦片、地点与缩略预览已加载，必须在实际浏览器查看；确认前mapConfirmed/thumbnailAcquired保持false。
- 打开候选位置，确认同名地点、行政区、覆盖范围、北向、河湖/主干路的整体关系。地图加载失败则尝试另一项，并在research.json的overview记录最终provider、url、status、viewedAt、scopeNotes与fallbackReason。两者都失败可用用户提供且许可明确的概览/开放地理资料；如没有，不捏造“已看过地图”，只继续不依赖地理的研究。
- 用户确需缩略图时，使用已配置且该用途允许的官方地图预览/静态地图通道，保留完整归属；缺配置不自动开通付费API。网页查阅链接、真实预览已查看、缩略图已合法取得是三个不同状态。
- Google平台条款限制抓取、缓存和从内容创建衍生数据，因此默认Google预览只作人工定位入口，不把截图送模型描路、抽建筑轮廓或去标识后转绘。百度也核对当次产品条款与授权，不因访问顺畅就认为可自由复制。两者缩略图均不默认进入开源包或原创视频背景。

## 独立核对地理与地方建筑

- 地理构图依据：优先用户拥有的地图/设计、当地官方开放资料或许可明确的开放地理数据；逐项记录来源、日期、许可、用途依据与实际核对状态。使用OSM等数据需保留其当次要求的署名/许可，不能把公开可看当公共领域。
- 建筑依据：查当地文旅/博物馆/建筑机构的一手介绍与许可明确的照片，必要时交叉核对。候选选择取决于区域范围与辨识度，可是塔、桥、屋顶群、城门、港口，也可以是当地住宅类型；不固定每城凑五个著名景点。
- 每个地标记录名称、位置关系、至少两个可画的辨识特征、参考URL/本地材料和复用依据。例如屋顶轮廓、塔层节奏、桥孔结构、墙体颜色；不能只写“某某塔”却继续画相同小方块。
- 经纬度记录原坐标系和来源，常见WGS84/GCJ-02/BD-09不要混用；不从截图像素猜坐标。需要转换时使用有依据的转换工具并保留原值/原系/目标系/方法，避免多次转换；本工具不内置或假称完成坐标转换。

## 再设计可审阅构图

地点与季节核对后，并行按[地点声音选材](location-sound.md)研究本片音乐和环境声，另存sound-plan.json；图像地图不提供录音地点或音乐授权依据。大小城市均查地方线索；缺本地材料按文化区域/省域/相似地景/原创回退并记录实际来源。map_plan.py只处理构图字段，不自动验证声音计划或选择音乐。

保存research.json（`map-research/v1`）：place、overview、sources、elements、geographyTreatment、cameraRoute、loopTreatment。参考[明确虚构的工程夹具](../assets/map-postcard/research/example.json)，不要把它当真实研究答案。

- place：中英文、季节、范围、朝向，真实坐标加coordinateSystem和关联sourceIds。
- overview：最终Google/Baidu选择、实看状态和失败回退；仅生成链接不填viewed。
- sources：id、URL或本地引用、reviewed、license、rightsStatus（user-owned/open-license/explicit-permission）、useBasis。字段是执行者核对后的声明，机器无法确认授权真假。
- elements：河道/道路/绿地/landmark，world box[x,y,w,h]、sourceIds、构图理由；地标写features与草图shape。构图不是新加的素材锁，真实参考文件仍按原素材机制登记。
- geographyTreatment：保留什么位置/连接、哪里压缩/旋转/夸张，明确“艺术化示意、非导航”；真实地理不能为了循环强行改成正弦河流。可在首尾用非地标绿地或水面缓冲、往返路线/开合遮罩衔接；地标不重复出现成两座同名建筑。
- cameraRoute：上到下先看谁、谁做主视觉、动态交通与负空间在哪。固定正俯视下，建筑也可以用屋顶、轮廓与地面符号辨识；重要立面需要选择局部插图/倾斜视角并在原方案中说明。

```sh
python3 scripts/map_plan.py /path/to/research.json --out /path/to/new-composition
```

输出composition.svg、composition.md和绑定研究SHA的handoff.json。SVG是**构图草案**，建筑形状仅作布局占位，标注依据/理由供代理继续重画；不是精细地标完成，也不自动替换map.js。缺研究、平台截图进入转绘链、地标无辨识特征或相互遮挡会报错；输出拒绝覆盖已有目录。

## 接回一次方案选择与成片

将位置概览状态、地标候选、原创构图、季节色板、镜头路线与声音计划合成原来的一份决策包。按[配色与视角](map-art-direction.md)记录选色依据：用户要求优先，结合地貌/水色/建筑、季节和氛围，自选同色系/邻近色/对比色等关系，写明主辅/强调色、明度层次与各功能色，再写入paletteOverrides；示例色卡不是固定答案，不从地图底图的道路标注/品牌UI直接取色。颜色为艺术化表达时说明保留的地方线索。镜头按既定单视角或一片多视角推进；相机可改变，不改变地标的岸别与位置身份。声音候选说明匹配依据、许可/费用与试听状态，不新增开场音乐问卷。用户已确定地图风格就展示该方向的构图，**不重复五选；仍须展示真实四帧拼图并确认后完整渲染**；用户只要求先看构图则交到构图为止，已有整片授权就按原范围准备代码/样帧，四帧确认后继续完整渲染。实质改变锁定内容/风格才处理受影响确认。

接着按地标特征重写当前项目的场景/几何，与固定世界、相位和镜头共用时间轴；复查桥是否跨河、建筑是否侵入道路、前后关系是否正确。已锁来源/参考/导流改变仍候选diff审阅。调用原PNG/配乐/未遮罩与编码接缝工具、最终观感与声音检查；换地方就重做地点研究和代表帧，不能复用旧城市核对结论。

## 已查官方入口与边界

- [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)：位置链接不需API key。
- [Google平台条款](https://cloud.google.com/maps-platform/terms)：3.2.3抓取/缓存/衍生内容限制。
- [Google地图图像指南](https://about.google/brand-resource-center/products-and-services/geo-guidelines/)：署名、视频与宣传用途条件。
- [百度开放平台](https://lbs.baidu.com/)：从当前官方文档核对具体预览/静态图产品和坐标说明；历史文档地址可能跳转，跳到首页不算已核实接口。

本版提供双入口连通性检测与构图交接，不包含Google/Baidu静态图下载器或第三方坐标转换；必须实际配置/测试后才标那些通道可用。
