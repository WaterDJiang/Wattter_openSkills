# 剧本之后，由用户选择风格

## 时机与边界

视频制作顺序：**理解内容 → 生成/改编剧本 → 推荐候选 → 用户选定 → 完整分镜与视觉实现 → 原制作管线**。

风格选择是本 Skill 的明确交互节点。用户已经选过的风格继续有效，不重复索要批准。一般的“直接跑完”“别逐站确认”只免除后续逐站确认，不能替代尚未作出的风格选择；若用户针对本片明确说“风格你来定”，则记录该委托并选择，不再反问。

只写剧本、技术分析、已有视频的无关小修时，不额外设置本节点。原文明确指定的画风，或当前对话已经明确选定的画风，作为已有选择；单纯提供参考视频不自动等于要求照搬其中所有风格。

## 先形成可供判断的内容

- 新工程先按制作契约 init 空目录，再保存这些文档；初始化只复制基础文件，不代表已选择模板画风。
- 先保存 `script.md`：核心信息、故事或论述主线、可见动作、旁白草稿、估计时长。现成剧本做必要视觉化，保留原意；文章/主题先编成适合动画的内容。
- 新主题在该文件内按[内容结构候选](story-and-timing.md#内容结构候选与取舍)比较有意义的结构并择优；内部取舍不是要求用户再选一次故事。用户已锁定内容时跳过重编。
- 此时可写粗分镜和依赖调查，不提前定死画风、生成整片视觉资产、写完整场景或导出成片。
- 先查[完整分类](classification.md)或 `python3 scripts/catalog.py list --purpose 用途ID`，按需读候选的 `references/styles/<id>/STYLE.md`。选定后读取同目录完整SOURCE.md并按[风格保真](style-fidelity.md)确定本片关键机制；来源示例故事不进入本片。再阅读 [组合画法](style-catalog.md)，用剧本中具体镜头解释选择；不只说“高级”“震撼”“适合传播”。

## 从具体用法检索，不按风格名猜题材

- 用[主题用法映射](use-case-mapping.md)识别广告、个人宣传、纪实、爱情、概念解释等具体任务；用途是目标，浪漫/悬疑是叙事情绪或类型，材质画风和引擎另判。同一个题材可以跨入口，例如环保广告查品牌广告与公益，个人纪录片查个人宣传与纪实。
- 执行 `python3 scripts/catalog.py list --use-case 个人宣传` 等命令。中文别名可定位；交叉用法分别检索合并去重，不强迫用户先选一个分类。可与 `--purpose`、`--query` 组合取交集；空结果放宽检索并说明原因，不代表内容不可制作。
- `primary`表示机制直接适配该用法，`conditional`表示需改编或额外条件；不是推荐分数或实现等级。逐项核对当前素材、事实、技术与时间条件，未满足的写缺口或剔除，不能把有条件选项包装成开箱即用。
- 映射的标题/关键镜头是未渲染构想，用来说明表达可能性。已有工程样片单独引用，只证明同风格的既有范围；正式内容按用户输入重写，不把构想复制成固定剧本。
- 在 `style-options.md` 每行理由中带匹配用法ID和“本片动作→媒介机制→可见结果”，同时写未满足条件。映射之外有更贴合的方向可推荐，补具体依据；这不自动修改目录。用户已指定风格或个人风格时沿用，不因映射未列出而改选。
- 要参考现成高关注作品时，用 `python3 scripts/catalog.py cases --use-case 用法` 检索[案例依据](production-cases.md)，按[案例选型](case-driven-techniques.md)分清原片技术事实与本片建议。互动网站的视频示范不等于有现成MP4渲染器；模型导演的混合素材不等于纯前端绘制。关注数不直接决定推荐次序，优先本片内容与素材条件。

## 提供 5 种方向：1 个首选推荐 + 4 个备选

输出保存到 `style-options.md`，使用短表：

| 选项 | 风格方向 | 对本剧本为什么合适 | 同一个关键镜头会怎样呈现 | 必要限制 |
|---|---|---|---|---|
| A（推荐） | 主风格；需要时附一种辅助形式 | 对应具体情节/信息表达 | 写角色/对象、动作、材质 | 仅写影响选择的限制 |
| B | 与 A 有明显视觉差别 | 同一内容的另一种表达理由 | 使用与 A 相同的镜头比较 | 同上 |
| C | 第三种可执行方向 | 说明取舍 | 仍比较同一镜头 | 同上 |
| D | 第四种可执行方向 | 说明不同的表达优势 | 仍比较同一镜头 | 同上 |
| E | 第五种可执行方向 | 说明适用条件与取舍 | 仍比较同一镜头 | 同上 |

- 推荐项放第一位，但不预先采用；不要将“A 推荐”写成“已选 A”。五个选项都必须可承接用户内容，不用明显差的选项凑数。
- 默认展示与当前剧本相关的五种，另说明可自定义、要求更多风格或选择有目的的混合。用户要求看全部时展示目录摘要。
- 每次从当前剧本重新筛选，不能固定五种组合或只改名称/颜色凑数；不要只因起步模板已有实现而反复推荐同一组。内容相近可以重复风格，但必须写出本片具体理由。
- 每项同时给出适合的制作类型、声音/节奏安排，以及会影响选择的实现风险；耗时有实测就注明条件，无实测写待小样验证，不沿用参考文章的数字。
- 用户需要看画面或关键差别难以用文字表达时，可在独立 probe 工程制作一张关键帧或短动态小样，标明候选，并放进同一次选择；不提前制作整片。主工程已锁的素材仍只能在候选目录变更，不能借小样更新主工程验收。
- MG 是表现形式，混合画风是编排方案；不要拿库名与艺术风格并列让用户选。
- 没有五种合理可行方向时，说明约束，给实际可行选项，不承诺不具备的工具。对需新实现的风格标“按本片实现并验证”；涉及 2D 黏土近似/真实 3D 等效果差别时写清。
- 用户选择混合时，给明确主风格、辅助风格和使用镜头；若用户已经明确了组合，直接记录。只有影响全片的组合关系仍不清楚时再问一次具体问题。

## 收集选择与等待

优先用支持五个选项的交互提问工具发一个问题，选项文字为 A/B/C/D/E 的实际风格名，首选推荐排第一。问题注明可自由输入自定义方向；工具自带自由输入时不要另造“其他”占位选项。工具不足五个选项时，在问题正文完整列出五项并用自由文本收集字母或风格名；没有工具时用一条简短问题列出 A–E。不得因工具按钮限制截成三项，也不拆成多轮强制选择。

提问模板（风格名与理由须按本片生成，不固定组合）：

> 本片讲【核心内容】，预计【时长】。A【首选风格】：【关键镜头的呈现与推荐理由】；B【风格】：【同镜头差异】；C【风格】：【同镜头差异】；D【风格】：【同镜头差异】；E【风格】：【同镜头差异】。你选哪种？可以回复 A–E、指定其他方向或组合。

没有明确回复时保持待选：

- 保存剧本与候选，`style-choice.md` 写 `status: pending`。
- 不把超时、预选按钮、沉默或历史其他片子的偏好当作本片确认。
- 可继续查素材/依赖等不依赖风格的准备；不能进入依赖选择的完整视觉制作；上文独立且明确标候选的小样仅用于辅助选择。若需要结束当前轮，明确“剧本和候选已保存，等待风格选择”，不要报告整片已完成。

## 记录与落实

`style-choice.md` 是本片风格决定的唯一记录；不要给 brief、分镜和工程各写一套冲突的审批状态。

```text
status: pending | selected | delegated
script: script.md
options: style-options.md
selected_direction: 未选择时留空；选择后填写实际方向
primary_style: 风格目录 ID 或自定义描述
supporting_styles: 可为空；写使用范围
presentation: MG / 跨风格叙事 / 无等
user_basis: 用户本片选择的原话及会话位置；不是模型推测
implementation_scope: 例如“前端 2D 黏土近似”；未知时写待查
```

- 用户选 B 就执行 B；不得以 A 更合适为由改回推荐项。用户已经明确风格则直接写 selected 和依据；明确委托代选则写 delegated、授权原话和实际所选方向。
- `brief.md` 和 `storyboard.md` 引用该记录，把决定落实为色板、笔触/材质、主体设计、动作与逐镜风格；选中风格先读取完整方法，在分镜写明不可删减的视觉特征、实际路线与观察位置。`film.json` 与 `scenes.js` 按完整分镜实现；目录 ID 不会自动激活渲染器。
- 用户改选时保留原决定与变更说明，更新同一记录，标出需重做的分镜、资产和画面；台词/旁白未改就不无故重写。
- 实现中需实质改换风格或将真实 3D 降为 2D 时，说明具体障碍和可选替代，等待该项决定。局部修正颜色、避开遮挡、优化速度且不改变已选风格时直接执行。
- 风格确定后继续完成已授权的成片制作，不再机械要求剧本、分镜、配音、导出逐站批准。
- 真实代码小样按[风格保真](style-fidelity.md)执行：有角色检查本片轮廓/表情/关键姿态与道具关系，无角色检查代表构图与原生变化；高风险动作先看连续帧再扩片。只有用户要求审分镜或出现实质改选才停下收决定，普通自查不设新审批。
