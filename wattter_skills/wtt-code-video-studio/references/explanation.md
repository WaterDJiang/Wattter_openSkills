# 解释模型与非视频分支

适用于知识与原理，也可支持产品机制、数据推演。不是所有故事都要建立数学模型。

## 先写四件事

- 要素与关系：方向、条件、阶段、位置，区分相关/先后/因果。
- 规则与依据：用户资料、可核对事实、理论口径、教学假设；示例参数明确标示。
- 变化与观察：观众改什么/镜头展示什么，结果在哪里变化。显示、图形和解释读同一份状态。
- 边界：模型/隐喻省略了什么；传统体系的内部规则不包装成已证实的现实因果。

| 理解问题 | 可选策略 |
|---|---|
| 组成、归属 | 分类/层级/拆解 |
| 反馈、约束 | 因果回路、联动机制 |
| 前后、时序 | 状态变化、时间轴、对照 |
| 位置、距离、路径 | 空间漫游、尺度缩放、参照物 |
| 输入怎样变成输出 | 流程、参数探索、机制隐喻 |
| 换一个条件怎样 | 对照实验、反事实 |
| 抽象观念怎样理解 | 类比、知识寓言、末尾映射与边界 |
| 不同视角不同解释 | 并置比较、观察者切换 |

主题不决定固定画法：玄学不默认关系盘，宇宙不默认粒子星空。主体可以是场景/事件/空间，不限定有零件的机器。

## 输出分支

- 文字：直接解释，必要时表格/字符图；不强制制作或确认。
- 静态：SVG保留可编辑文字，明确标题/标签/阅读路径；用户已有方向直接沿用，否则把内容/构图/图例作为同一次方案选择。
- 交互：优先离线原生HTML，每个控件对应解释问题，显示变化原因；模型与读数同源。检查键盘、窄屏、正常输入和边界。需要持续运动时有暂停与减少动态效果支持。
- 视频：模型由导演时间轴驱动，旁白可分段但连续镜头按 `director.group`组织。用 `director.reviewAtSeconds`覆盖关键动作；至少在最终编码后再次检查。
- 视频+交互：共用模型与绘制层，控制入口分别来自时间轴和用户操作；不强制所有视频先制作完整交互页。
