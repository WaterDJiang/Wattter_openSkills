# 四帧拼图审阅

适用于视频新片和会改变画面的修订。用户已指定风格免五选，但仍先审四帧；纯文字/剧本/静态图不执行视频帧门。与素材变更审阅、最终编码审阅分别记录。

## 展示什么

用本片真实代码和当前配置生成四张不同时间点的样帧，拼成2×2图；每格标帧号与秒数。覆盖建立构图、核心变化、重要细节和收尾；有开合时避开全白的首尾，不能拿空白图过门。默认抽样只作起点，导演按剧情指定帧号。高风险动作先另做连续小样自查，静帧不证明运动或声音。

用户看到的内容包括：拼图、对应剧本/核心动作、预计或已配音的真实时长、声音安排与本次待查项。未确认不完整渲染。用户指出问题就保存候选并修正，再出新版本；不让用户审批每个技术步骤。

## 通用工程

完成素材锁/真实配音校时/混音后：

```sh
node tools/render.cjs . --preview
# 可按本片剧情指定四帧，具体参数见render.cjs --review-frames
# 将输出中的contactSheet以实际图片展示给用户，等待其确认
python3 tools/preview_review.py approve . --version v0001 --message '用户对这版四帧的明确确认原话'
node tools/render.cjs . --render
python3 tools/pipeline.py finish .
```

上面的确认原话是说明格式，不能照抄当真实批准。approve只记录对话授权，不替用户决定；普通“继续”、风格选项或自动自查不算四帧认可。要使用prepare输出的实际版本，不猜v0001永远最新。

## 指纹与重跑

prepare生成版本化manifest与拼图，保存四张图/帧号/时码、fps/总帧数、当前实际加载源码与配置、时间轴/素材锁指纹。确认引用该manifest版本和拼图哈希；历史保留在.preview-review/versions。

执行前check核对记录、源文件、四图和拼图，缺失/变化/未批准均阻断完整render和成片验收。导出器在进入完整导帧前，按已批准的四个帧号重新绘制并核对PNG哈希；字体/运行库变化导致重画不同也会阻断。同一批完全一致可复用；重写源码、换素材/配音时序或替换图像后重新生成并展示，不能改哈希冒用旧记录。改素材先走素材候选审阅；仅改代码不触发素材确认，但画面审片仍需有效批准。

地图Node专项复用同一个preview_review.py，binding.kind为map；以冻结的绘图依赖/config和参数为依据，不要求虚构film.json。先导预览/拼图，用户确认后在同一已冻结输出目录继续完整导帧；原作品不覆盖，变更在新候选目录。实际命令见[地图模板](seasonal-map.md)。

## 最终状态

四帧确认只批准继续制作，不表示最终MP4、主观听感或用户采用已通过。完整导出后仍按[视频质量](video-quality.md)生成真实编码证据并审阅。没有用户确认时，交付“样帧预览，待确认”，不得为了测试或交付伪造批准。
