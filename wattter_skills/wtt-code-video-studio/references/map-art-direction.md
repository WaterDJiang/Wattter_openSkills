# 地图的配色与视角

地点、画风、相机分别设计。地图明信片不限定为低饱和纸色，也不限定固定俯视下移；沿[季节地图](seasonal-map.md)保留原2D路线，同时可按内容实现等距/斜俯视或同一场景多视角。真实地点仍先研究地理、地标和季节。

## 从参考提炼什么

用户截图中的两张独立卡片可确认俯视农田和等距街区两种画法，以及鲜明色块、细轮廓、纸白边界、局部颗粒。截图不能证明单条原视频如何转场或相机运动，也不能当作其源码。只学习表现方法，自绘地形、建筑和纹理，不搬运截图/成片/模型。

- 配色：新地图优先推荐鲜明粉彩，让黄/绿/蓝/粉等主体色形成区分；纸白与低饱和色留给边框、留白或次要区域。用户指定安静/档案/水墨等方向时按其意图用色，不机械拉高整幅饱和度。
- 层次：地面、道路、河流、树冠、建筑侧面/屋顶用不同功能色；轮廓保持清晰，纹理局部使用，避免灰蒙滤镜覆盖全画面。
- 地方依据：河流、树种、季节与建筑的辨识特征继续核对。可艺术化配色并说明，不能为了跟参考颜色一致把赭黄黄河套成蓝色，或把当地秋树全换成樱花。
- 体积：俯视可保持平涂；等距/斜俯视以正侧顶面色差和高度表现体积，可不做写实投影阴影。“无阴影”不等于所有立面必须同色或只画小方块。

## 两种多角度交付

| 交付 | 使用场景 | 制作要求 |
|---|---|---|
| 同地不同角度各一支 | 系列卡片、不同渠道版本、用户要比较画法 | 共用研究/地标与素材依据，各自完整构图、循环和验收；不能用一张静帧充当另一角度视频 |
| 一支内连续换角度 | 同一地方既要地理关系又要建筑/街区体积 | 同一世界坐标/高度、标识和动态对象随相机投影；按内容安排建立→变化→停留→返回，起止相位闭合 |

声音与原方案合并讨论，推荐方向里一次写清配色、视角、相机变化和素材需求，不新增开场模式/逐维问卷。已经指定画风或参考、委托代选，就记录本次决定后继续，不重复五选。固定20秒不是全Skill要求；短片也不强行塞多次切角。

## 可复用实现

[presentation.js](../assets/map-postcard/presentation.js)提供纯函数小组件：

- `palette('vivid'|'soft', overrides)`：纸白、轮廓、河流/植被/墙面/屋顶/道路等功能色；覆写本地河水或季节色不改变其他城市的默认。
- `cameraAt(frame, {frames:600, profile})`：`top-down`固定俯视；`isometric`固定35.264°仰俯角与45°方位的等距方向；`multi-angle`为俯视→两侧斜俯视→返回的周期示例。它是镜头参考，不是每片强制同一节奏。
- `project([x,z,height], camera, options)`：实际几何投影；高度随倾角改变屏幕位置。倾斜整张既有2D画布、缩放/旋转旧MP4，不算实现新的建筑视角。
- `orderedFaces(faces,camera)`：显式`layer`优先，再按平均深度排序；地面层先画，立体面再排序。大型相交面/长桥面按物体或跨拆分；该方法不是通用深度缓冲引擎，复杂穿插换适当3D后端，不靠硬盖遮挡掩饰。

组件没有自动创建任何城市的建筑。复制到新工程，由该片map.js显式调用、按独立地点研究重画几何和高度；原map-postcard/map.js、index.html和export.cjs仍是原2D俯视示例，**不读取视角配置，也不因旁边有该文件就自动变成立体**。浏览器先加载presentation.js再加载场景；Node用require读取相同组件。新文件进入渲染源码指纹，不能漏掉依赖哈希。

```js
const camera = PostcardPresentation.cameraAt(i, {frames:600, profile:'multi-angle'});
const colors = PostcardPresentation.palette('vivid', {river:'#DDBA4E'});
const p = PostcardPresentation.project([x,z,height], camera);
```

这里示范调用关系，不是完整城市渲染代码；所选路线仍先做代表帧和高风险动作再扩全片。Canvas投影不强制安装Three.js；实际几何/光照/复杂遮挡需要时另选引擎并验证。

## 标签、节奏与循环验收

- 同一地标跨视角保持形状、岸别、位置与颜色身份；重要建筑完整停留到能认出，不用频繁切角掩盖低细节。
- 先画几何，再按世界锚点绘制屏幕文字；字号保持可读，不随地面压扁。每个关键视角都检查标签碰撞/遮挡，不把物件名直接埋入几何。
- 相机和人物/交通/水车等从绝对帧计算；先确保首尾相机姿态/目标/尺度及物体相位一致，再测像素接缝。首尾淡出成白不能代替相机和未遮罩世界检查。
- 检查每个关键角度与转角窗口：底面压住高物体、长面覆盖前后景、标签互盖、物件突然消失、道路/桥岸连接断开，都要在正式导出前修正。
- 技术通过、代理实际看帧/连续窗口、独立创作对照、听感和用户采用分别报告。程序只证明参数/确定性/绑定，不能自动给配色“更好看”的结论。
