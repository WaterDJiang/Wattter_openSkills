# 剧本、镜头和动态时长

## 从内容选择结构

| 用户输入 | 推荐组织方式 | 常见失误 |
|---|---|---|
| 一个想法或观点 | 具体困境 → 尝试/发现 → 结果 | 只有口号，没有可见的变化 |
| 产品或能力介绍 | 使用者的任务 → 能力如何改变过程 → 实际价值 | 宣称没有验证过的效果 |
| 科普、课程或复杂内容 | 问题 → 机制 → 例子 → 应用/回扣 | 长文逐段变成字幕 PPT |
| 已有故事/剧本 | 保留人物动机和因果，再视觉化 | 为炫技擅自改变故事含义 |
| 氛围、诗句、音乐主题 | 意象建立 → 变化 → 情绪落点 | 强塞解说或固定三幕模板 |

剧本可以是叙事短片、动态图解、演示动画或混合形态，不要求每部都有冲突反转。文字用于补充画面表达不了的部分。一个镜头主要承担一个新信息点；复杂知识允许多镜演示，不在一张画面上堆满结论。

## 按表达目标寻找可见变化

比较结构时先确定受众要记住的能力、知识、情绪或态度，再确定观众先看到什么、期待什么、接着有什么变化及其落点。它是构思和核对工具，不是所有片子必须遵循的四段模板；已有剧本和指定结构优先。

| 目标 | 可选结构 | 适合代码动画的核心动作 |
|---|---|---|
| 证明可验证能力 | 挑战 → 演示 → 结果 | 让路径、状态、数据或前后条件发生可观察变化；依据不足时标示为示意 |
| 让简单卖点易记 | 目标 → 阻碍 → 夸张升级 → 回收 | 对象在清晰规则内变形、复制或遭遇意外；夸张不冒充真实功效 |
| 展示使用价值 | 人物任务 → 尝试 → 产品改变过程 → 结果 | 同一任务的关键步骤或状态变化承载作用，不凭空虚构收益 |
| 表达知识机制 | 问题 → 机制变化 → 结果 → 必要解释 | 用因果关系、变量和对照呈现成立条件，类比注明边界 |
| 唤起情绪或立场 | 意象/处境 → 有意义的变化 → 情绪落点 | 用画面、运动或声音建立变化，避免强加角色冲突 |

结构按表达目标、材料和可制作性选择，产品类别不决定唯一写法。创意从“同一信息能被什么动作或变化看见”出发：先写内容动作 → 动画机制 → 观众看到的结果；仅选视觉特效不算构思。反转需有可理解的铺垫，真实事实和功效须有依据；重做具体动作与结尾，不照搬参考作品。结构候选继续遵循至多三种的规则，与五种风格方向分别判断。

## 内容结构候选与取舍

对只有主题、想法或允许自由改编的材料，在 `script.md` 开头比较至多三种有实际差别的结构：每种写开头、核心动作/论证、结尾、为什么适合，以及素材/时长代价。模型择优并说明理由，再发展脚本，不另建剧本确认节点。只存在一种合理结构时说明约束，不凑三个；已有剧本、锁定台词顺序、指定结构或仅做局部修改时直接沿用。

候选围绕内容关系生成。例如个人宣传可比较“一个项目从问题到结果”“三件作品共同说明一种方法”“一次职业转折”；概念解释可比较直接模型、对照实验或寓言后揭示。它们不是画风选项，不把所有内容都改成冲突反转。必要时查[主题用法](use-case-mapping.md)的结构起点，但不照搬示例题目。

先形成自己的开头、主动作/论证和结尾，再读对应样片的剧情、时间线或源码。材料型纪实先核实可用证据再定结构；允许先用素材检索工具，不因此继承样片叙事。候选风格的方法说明可先读。复杂风格可选一两项标杆说明学习的材质/节奏与不采用的设计；不要凭记忆假称已看过参考作品。

选定方向后在现有分镜中落实代表镜头、原生变化、音乐/环境/动作声与时间依据。参考和既有样片只借方法，开头、关键动作和结尾若与示例同构则重新设计；不为形式指标强加镜头数、静默次数或固定时长。

人物的回应承担情绪转折时，在该镜声音栏写清「原声保留到哪一刻、音乐跟哪个动作进、最后一音落在哪」。只交分镜时交这行设计；进入试剪再按[用短乐句回应人物动作](rhythm.md#用短乐句回应人物动作)贴画试听。

## 可选写法：寓言式概念揭示

适合抽象概念、机制科普，或用户明确要求“先讲故事、最后才懂”的内容。结构为 **处境与目标 → 行动及后果 → 线索累积 → 临近故事结尾揭示 → 故事结束后解释概念**。它是叙事写法，可与沙画、粒子、像素或其他画风组合，不增加开场模式选择，也不替代所有科普的直接讲解结构。

- 用户已给概念或主题就沿用；只有允许自由选题时才从相关领域选择。用户要求研究生水平时保留相应机制深度，否则按受众选择难度，不为显得高深换成无关术语。
- 创作前先在 brief 的内部说明写清概念含义、必要条件、故事元素与概念机制的对应关系、不能类推的部分。专业概念核对可靠教材、原始论文或官方资料，记录来源；待核事实不能用虚构结局补齐。
- 用角色的选择、可见动作和后果呈现机制；伏笔必须足以支持结尾理解。可以延迟命名，不能为悬念藏起理解因果所需的条件。删掉概念名后故事仍须成立，揭示后也不能只是给通用人生道理贴术语。
- 观众侧标题、开场旁白、字幕与画面标签避免提前点破答案；内部 brief 和分镜可以明确写出概念。用户锁定的标题/原文优先，若已经点题，就保留其要求并说明悬念范围受限。
- 在故事接近结束、机制已经可理解时让观众意识到所指概念；正式名称可在揭示镜头或紧接的解释段出现。不固定在某个秒数或百分比，不为拖延答案新增无用情节。
- 故事结束后另设解释段：准确名称与定义、关键情节逐项映射、必要条件与类比边界；按需要补公式、图解或应用。寓言明确是虚构，不能称真实案例、实验或理论证明。解释段与故事共同计入片长、旁白和字幕预算。
- 已有剧本且用户要求保留时，不自行改写成寓言；硬时长不足时先删装饰，仍不足按既有内容取舍规则处理，不删掉必要解释来保住反转。

采用此写法时，在现有 storyboard 表的“内容目的”中标记铺垫/线索/揭示/解释；另在该镜头备注写“观众此时知道什么、内部对应什么、是否首次揭示术语”。不把内部概念映射直接复制到提前出现的字幕。解释镜头复用前面的角色、道具或关系图，让观众看出对应关系；不规定画风或新增 film.json 字段。

可复制的编剧提示词（按本次内容填写，不机械套用）：

> 围绕【用户给定的主题或概念；允许自由选题时选一个相关概念】，面向【受众】写一个可制作成动画的寓言。若本次要求研究生水平，保留这个层次的关键机制。先在创作说明中核对概念、条件与故事映射；观众看到的故事不要一开始就说答案。用具体行动、后果和伏笔间接讲清机制，尽量到故事快结束时才让人意识到所讲的概念。故事结束后解释其准确含义、情节对应关系和类比边界。再给出可见动作与粗分镜，标明线索、揭示点和解释段；风格确定后细化完整分镜。时长按故事与解释的实际需要估算，遵守用户给定上限，不固定为 30 秒。

编剧审阅逐项检查：揭示前是否泄题；线索是否呈现真实机制；结尾是否能由前文推出；解释是否准确且说明边界；故事与解释是否都已计时。任一项缺失就修稿，文本符合规则不等于观众已经理解。

## 写成可制作的剧本

结合 [制作类型与导演方案](video-formats.md) 选择观看结构，不把像素/沙画等画风当作故事类型。

`brief.md`：目标受众、核心信息、画幅、声音、明确的时长约束与估计范围、素材来源。风格未定时标待选；选定后引用 style-choice.md，不自行填入推荐项冒充决定。

`script.md`：标题、故事/论述主线、每段视觉动作与台词、结尾落点。用户给了事实则建立来源映射，不因改写丢失关键限定条件。

### 让观众只看片也能复述故事

用于依靠人物选择或事件转折传意的片子。编剧先用两句大白话复述：谁想做什么，实际发生了什么；看到这个结果后，谁做了什么。把观众必须知道的关系、目的放进可见的日常细节或一句自然对白。悬念可以留到后段揭示，氛围片按它想让人感受到的变化取舍。

分镜时把关键因果落实到现有的「内容目的」和「动作/效果起止状态」栏。逐镜问：观众凭哪件东西、哪个动作知道这件事？例如修表师为顾客修好旧表：交表时秒针停在刻痕旁；表冠拧过，秒针第一次越过刻痕；顾客把原本打算收进口袋的表戴回手腕。故障、结果和人物反应都有镜头能指认。两个人对同一件事有不同理解时，分别给出两人的视线落点，再让观众看清各自留下的结果。

试剪先单独播放，再附分镜说明。按播放顺序复述人物目标、转折及结尾的选择，指出对应画面；原本写在剧本里、播放时却只能猜出的那一步，就是返工位置。优先补一次特写、一个反应或道具的前后状态。给观众留出辨认结果的时间，按实际动作与对白调整片长。保留开放的情感解读。创作者自查与首次观看者的真实反馈分别记录。

### 从转折读到表达

先在 script.md 的关键段落写一行「原文动作或事实 → 开始/结束状态 → 观众何时得知 → 视听依据」。只有主题时可补一个创作假设；已有剧本引用原动作，尊重锁定的台词、顺序和叙述视角。挑会改变理解的段落，依内容拆镜，一个长镜头也可包含几次变化。

- 人物与故事：区分想做什么、受到什么阻力、外表如何掩饰，以及观众的感受。例如人物笑着道别，手却把车票折了两次；决定是否提前让观众看见那双手。[Pixar 角色课程](https://www.khanacademy.org/partner-content/hass-storytelling/storytelling-pixar-in-a-box/ah-piab-character/v/character-3) · [希区柯克谈观众信息](https://dlg.usg.edu/record/ugabma_wsbn_wsbn42133)
- 风景与意境：写下观察位置、近远声和最后仍在动的对象。秋江雨停后，近处滴水渐稀，远处摇橹声渐清；同一地点也可从慢看改成晨市苏醒。[宫崎骏谈动作间的留白](https://www.rogerebert.com/interviews/drawing-on-spirited-world)
- 科普、产品、数据、纪实：写出原先的猜想、可核对的事实、哪次对照改变认识。保持比较尺度与单位，用声音或遮挡控制揭示顺序。事实来源、创作示意和未证实的推断分别标识。[Segel 与 Heer 的数据叙事研究](https://vis.stanford.edu/files/2010-Narrative-InfoVis.pdf)
- 在 storyboard.md 的内容目的栏写观众变化；在构图/动作栏落实景别、视点、留白和注意中心。把关键镜头连看一遍，检查情绪是否只靠旁白，画面疏密、光色、声音在哪个动作上改变。粗分镜阶段用构图小稿比较。[迪士尼故事板流程](https://www.disneyanimation.com/process/story/) · [视觉开发](https://disneyanimation.com/process/visual-development/)

整片一条龙在剧本形成后执行 [风格选择](style-selection.md)：从 [目录](style-catalog.md) 推荐方向，等待用户决定（已有选择或明确委托除外）。用户要求先交分镜时可直接完成机位、动作、声画关系与接镜设计，把画风留到下一次逐镜指定；见[分段创作](staged-creation.md)。

选定后，`storyboard.md` 使用稳定镜头 ID。最低字段：

| ID | 内容目的 | 景别与构图 | 主体/身份 | 风格 | 动作/效果起止状态 | 技术与选型理由 | 转场/资产 | 旁白/字幕 | 音效 | 预计秒数 |
|---|---|---|---|---|---|---|---|---|---|---|
| 示例 shot-a | 让观众看出回忆逐渐清晰 | 中景、角色居中 | 同一角色 seed-hero | 沙画 | 轮廓逐渐显露，角色轻摆 | Canvas 遮罩与固定沙粒，显影对应回忆浮现 | 下一镜继承已显露轮廓 | 短句 | 最后一笔收拢时短擦，沙粒静止后留白 | 按动作与话长计算 |

每镜先写内容目的，再决定主体、动作/效果及技术，在用户已选的风格范围内展开，并说明理由。例如“一个沙画角色走过沙漠”同时包含角色与场景，不能强迫它在 character 与 sand 之间二选一。已有剧本保留原意；只有主题或文章时先生成/改编剧本，不直接把原文逐段贴到模板画面上。

制作后把时间轴实际值回填分镜。角色表只记录会影响复现的锚点：轮廓、头身比、颜色、眼口位置、服饰/道具和可用姿态。不需要图片生成也可以用代码画角色正侧面和表情表。

## 发声角色与逐句表演

只为真正发声的人物建立speakerId，旁白继续沿用已配置的defaultVoice；人物跨镜保持同一声线。角色可以用沙画、粒子或纸片呈现，视觉材质不决定音色。把角色身份与语气分开：疑问转欣喜仍是同一个人，不因情绪变化随机换声线。

在现有script/storyboard的台词栏逐句记录说话人、text、说话意图、实际可执行的instruct和句后停顿。先写清关系、目标和情绪转折，再安排必要的语气变化，不为每句机械叠加“激动、夸张”。intent只作编剧记录；当前Base克隆不接受非空instruct，CustomVoice固定声线可以接收逐句指令，具体配置见[配音指南](voice.md#角色绑定与表演计划)。不把表演标签写进会被读出的text。

同一视觉镜头可包含顺序话轮，不强迫角色轮换就切镜；cast和utterances字段见[制作契约](production.md#角色与逐句话轮)。每句先合成真实音频，再确定角色活动区间、字幕和停顿。先有稳定声线/表演要求，才实现对应高亮、表情或嘴部动作；未实现时不声称自动口型同步。

只要求声音测试时可交约10秒多角色小样，检查同角色声线稳定、转折语气、断句和漏字；不足时保留自然停顿，超时改台词重做，不加速或截断。纯音频不进入视频风格选择/四帧流程，也不新增强制音色审批站；实际试听、技术检查与用户采用分别记录。

## 估时与锁时

`film.json` 是内容与镜头预算来源；`timeline.json` 是从它编译出的执行时序，不手改第二份时间表。

- 初估中文旁白可从每秒约 3–4.5 字起步，按语气、术语和停顿调整。英文使用实际词速评估后填写预算；字符法仅用于粗略预览，最终一律以音频长度校准。
- `visualSeconds` 是一个镜头完成动作/阅读的最短时间，不是全片固定份额。
- 每镜公式：`durationFrames = max(ceil(visualSeconds × fps), leadFrames + voiceFrames + tailFrames)`。
- 新对白镜头将其中的声音部分换为`Σ(各句voiceFrames + 各句pauseFrames)`；每句音频与pauseAfterSeconds各自向上量化为整数帧。句后停顿与镜头tail分别计入，不靠文本字数猜多角色切换时刻。
- `voiceFrames` 在估时阶段取文本粗估，在锁定阶段取 FFprobe 音频时长向上取整。每镜起止为半开区间 `[startFrame, endFrame)`；镜头无重叠，总时长为 `totalFrames / fps`。
- 需要交叉转场时，在一个镜头内部预留转场段并绘制前后两个状态，不在时间轴里再重复扣时。下一镜首帧接住末态。
- 无旁白镜头由动作、字幕阅读和音乐节拍决定时长；不要靠 TTS 规则压缩视觉叙事。
- 旧旁白字幕按整镜字符权重近似切分；新对白先按每句真实起止编译speakerId/utteranceId，再在该句内部近似定位，不把全镜字数当作多人同步。要求词级精确时使用真实转录/强制对齐结果并扩展字段/编译器，不能将近似分配称为逐字对齐。

## 长片处理

内容自然需要数分钟时，先划分章节和段落，再分配镜头。既没有 30 秒上限，也不把所有镜头固定成相同长度。检查长时间纯文字、相同构图和重复动作是否有叙事依据。

导出每次只保留当前帧，内存不累计全部 PNG。重纹理和目标粒子预计算，但不要缓存数十万张完整画面。当前脚本从头流式渲染，不内置断点续渲。特别长的片子如需分段导出，先增加支持全局帧号的区间接口并验证接缝，再启用；不能声称已有此能力。

硬时长与完整内容冲突时记录“当前需要多少秒、超出多少秒、删哪部分能满足”，把内容取舍交还用户。没有硬限制则按内容完成，输出实际长度。

## 音乐驱动与贯穿母题

音乐驱动的片子把已核对拍点及动作事件写入 film.rhythm，音效用 startBeat 共享全局整数帧；编译器不自动改变镜头时长。段落旁白、长镜头停顿仍按内容需要安排，不能机械每两秒切画面。

历史/科普长片可给一个贯穿对象稳定身份，让它的能力、环境或关系逐步变化；分镜写出每次变化的因果、空间接续和来源。知识准确性与画面隐喻分别核对，避免把拟人化演示称为真实机制。循环片首尾检查位移/速度/声音连续，不通过重复首帧制造停顿。

## 从分镜到用户审片

方向选择只维护在[选择流程](style-selection.md)，完整导出前只维护[四帧审阅](preview-review.md)。storyboard安排四个判断画面和必要动作检查，不在编剧页重建批准字段。
