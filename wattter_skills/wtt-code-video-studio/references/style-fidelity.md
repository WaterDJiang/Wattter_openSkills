# 风格保真与技术落实

在风格选定、用户委托代选，或明确要求风格样例/测试后读取。候选阶段仍用精简目录筛选；文字解释等无视觉制作任务不加载。本页复用已有剧本、分镜和审阅记录，不新增一轮审批。

## 从完整方法得到本片的制作决定

- 读取选中风格的完整SOURCE；本库自有风格无SOURCE时读取其专项参考。目录里的材质/动作摘要用于检索，不能替代制作方法。无需加载无关风格。
- 在现有分镜里写清：本片主体和动作；风格不可删减的视觉特征；承担这些特征的实现；在何处、以何种尺度能观察它们。用户指定技术时沿用；发现该技术无法满足关键效果，只说明并澄清受影响取舍。
- 从完整方法中的原生动作选择适合本内容的一种，如笔触成形、纸页铰接、分色叠印或空间拆解。配色、造型、相机、声音和节奏也按内容设计，避免多个风格共用一套主体加换色。
- 先形成本片内容与视觉意图，再从固定来源的DEMO及相关引擎学习实现。上游路径由 `config/reference-index.json` 的固定commit和slug定位；源码没有本地收录时可按实际网络读取并记录来源。不能把SOURCE文字存在当作演示引擎已安装或已实测。正式作品替换参考的剧情、角色、品牌、镜头和音乐。

风格的“核心”是约束，具体算法可以不同。例如厚涂需要颜料厚度与侧光的可见关系，可以选等效实现；把几条短线叫作刀痕不能满足这个要求。用户明确只要简化外观时可按其范围制作并标明，不能把近似当作完整风格的验证证据。

## 让视觉机制决定技术

现有浏览器导出器调用 `renderFrame(frame)` 并截取 `#stage`，不要求舞台必须是Canvas 2D。先复用它验证实际路线；技术名称与艺术风格不互相替代，也不要求一片使用所有库。

| 需要表达的机制 | 可用路线 | 真正需要看到/验证的内容 |
|---|---|---|
| 造型、笔触、矢量与排版 | Canvas 2D / SVG / DOM | 形体由对应线面构成；路径、图形和文字在目标尺寸可读 |
| 自然笔刷、排线、流场 | 自有笔刷或p5.js + p5.brush | 变宽笔带、飞白、透明叠色或该笔刷实际特征；固定seed与必要缓存/重放 |
| 厚涂、分色与逐像素材质 | Canvas多通道或WebGL shader | 高度/侧光、逐版网角/错位等实际机制，保留启用/关闭或参数改变的同帧对照 |
| 三维材质、遮挡与空间镜头 | Three.js / WebGL | 真实几何、相机与光照；玻璃透射、HD-2D精灵阴影等按片落实 |
| 界面、动态图形与多对象编排 | SVG / DOM + GSAP | 连续状态和遮罩、合理文字停留；暂停时间轴并按整数帧seek |
| 数据叙事与布局 | D3 + SVG / Canvas | 数据、比例尺、路径和注释同源；换数据时几何关系仍正确 |
| React多层视频合成 | Remotion，可组合绘图层 | 宿主帧时钟、多轨关系与真实导出；其回执不能由浏览器截图报告代替 |

Canvas能画高质量风格，换库也不会自动提高美术质量。实现应保留必要的造型细节、光影、材质、运动与空间关系；选择更简单的代码不意味着删除这些目标。

## 用短小样验证关键机制

最小单元减少非关键剧情，保留风格成立的机制。按实际动作确定尺寸、帧率和时长，不把统一4秒、统一低分辨率、同一个简笔人或方块当作全部风格的默认。

沿既有代表帧与动作窗口，选足以判断本片的证据：能辨认材质的近景、能看清主体与空间的整体、能看到原生动作的连续片段。不是每片必须三镜；同一镜可同时承担这些观察。去掉风格标题后仍检查画面是否体现预定特征；相邻风格容易混淆时并置比较。

| 示例目标 | 保留的关键观察 | 不足以证明目标的替代 |
|---|---|---|
| 厚涂 | 静止刀痕稳定，颜料脊线随侧光显出厚度 | 给短线换明暗色 |
| 玻璃 | 壳内外、透射和移动棚灯有一致空间关系 | 渐变矩形上移动亮条 |
| HD-2D | 像素角色与三维场景发生遮挡、受光/阴影关系，像素密度一致 | 平面方块加矩形角色 |
| 水彩 | 笔触构成形体，飞白/叠色与纸色留白服务场景 | 实心矢量主体上叠纸纹 |
| 孔版印刷 | 分色与叠印、网点和稳定错版对应同一对象 | 两个透明圆代表整条风格 |

这些是特征辨识例子，不是后续故事模板。未达到特征时继续修正，或明确交付范围；不能用“最小测试”把关键机制略掉。

## 把技术结果和视觉判断放回原记录

- 分镜/制作交接写实际路线、依赖与版本状态、关键机制及待查项；没有安装/运行时明确未实测，不预填成功。按 [画法选型](visual-recipes.md#帧契约适配)处理各库的帧时钟与就绪。
- 技术检查证明解码、尺寸、帧数、随机定位等；像素有变化、哈希不相同只能证明画面不同，不能证明风格成立。
- 在现有 `review.md` 或 `visual-review.json` 的观察/问题字段中记录预期特征、实际时间码/帧与判断。复用 [视频质量](video-quality.md) 的最终MP4证据与指纹，不建另一套通过状态。
- 方法收录、具体工程运行、风格审阅和用户采用分别报告。一个近似样例的成功不提升整类能力；用户指出同质化时保留该质量反馈，不以更多技术通过数量覆盖它。

上游材质与导演方法可参考固定来源的 [TECHNIQUE.md](https://github.com/lemomo-ai/lemo-opuscar/blob/bebbbe1aa92a3cb4bb6f83500e61b23a17d1aa00/TECHNIQUE.md)、[DIRECTOR.md](https://github.com/lemomo-ai/lemo-opuscar/blob/bebbbe1aa92a3cb4bb6f83500e61b23a17d1aa00/DIRECTOR.md)；原接口、时长、声音和素材流程仍沿本技能制作契约。
