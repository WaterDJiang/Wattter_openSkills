# 声音设计与节拍

## 有声分镜先做三件事

- **先听什么。** 每个转折只指定一个前景。音乐主导的段落，先拿到实际使用的剪辑版，听出乐句起落、重拍、停顿，再设计入画、动作接触和转场。对白主导时，先用实际录音定句尾和呼吸；纪实或安静故事可用街声、物件碰撞与留白定节点，一样能剪出节奏。
- **用什么声音。** 用户带来的现场录音、品牌声标或指定曲目沿用其授权范围；没有现成素材时，执行者按用途主动选材。真实空间优先找与地点、材质、距离吻合的实录，夸张动作或需要精确触发的细节适合程序拟音，音乐可选授权曲目或用开放乐器采样写原创乐句。保留可独立调整的对白、音乐、环境和关键拟音分轨，只建立这支片实际用到的轨。
- **在哪里变。** 在原分镜旁记录「声音事件 ID｜依据和时码｜画面的准备、接触或反应｜哪条轨退下、何时恢复」。已有音乐按实际剪辑后的波形核对重音，带前置静音的音效先定位听觉瞬态。提前入声可以预告下个空间，余音可以跨切点；同帧对齐用在确实需要同步的接触点。音乐长度、镜头或对白变化后复核受影响节点。

### 怎样选中一段配乐

粗分镜完成、正式锁时前，在关键段旁写一句音乐任务：观众此时在等什么，哪句话或哪个动作需要听清，音乐从哪个变化进入，又在哪个画面收住。可以只配一段。音乐驱动的镜头先核对乐句再编动作；对白或生活声主导的镜头先定原声，再试音乐何时进来。

- **找候选。** 用户指定的音乐优先核实可用范围。公开曲目按具体用途、情绪变化、乐器、节奏密度和所需段长检索，记录具体录音、许可、署名和可剪辑条件。可从风格的声音说明或地点研究取得配器线索。需要精确回应表演时，按镜头落点写原创短句，记录乐谱或合成代码及采样来源。样片音乐与拟音索引分别管理。
- **贴画试听。** 留一版原声作基准，把有取舍的候选剪在同一段画面上，覆盖入乐前的对白或动作、入点和尾音。维持原声电平和相同剪点，将候选音乐最响乐句调到接近的听感再比较。听哪版会提前泄露转折、遮住字尾，或让最后一个动作更清楚。节奏、起音密度与响度曲线可用于初筛。短片可以只比较一个合适的乐句与留白。执行者给出首选和理由，用户要选时提供真实试听；沿用已有审片节点。
- **记具体剪法。** 在现有分镜或声音记录里写「候选/来源与许可｜原曲入出点 → 片内入出点｜对白让位、重音、淡出｜取舍」。同一首跨段落时也记录跳剪和交叉淡化。原创用音符或演奏事件记录最后落点。选定的文件与 SHA256 按素材审阅入锁，未定版本保存在候选目录；要改已完成片的音轨时沿用[纯音轨修订](audio-revision.md)。

### 用短乐句回应人物动作

当观众要先听清一句话、看懂一个举动，才明白人物的心意时，在分镜的声音栏标出三个位置：**原声留到哪里、第一音跟谁的动作进、最后一音落在哪里并怎样消退**。对白和道具声承担交代，给它们留足空间。若镜头要制造预感，可以提前入乐；若原声已足够，可以整段留白。

例如，女儿问「拍到了吗？」，妈妈递来一张画。问话、翻页和看清画纸的过程保留原声。直到女儿重新举起手机，才轻轻拨出第一音；中间几音陪她取景，最有分量的一音落在给妈妈拍照的快门上。相册出现，听上一音自然衰减。这时温暖有了对象：女儿也想把妈妈留下来。

- 写原创乐句时，先把第一音和落音绑到本片动作帧，再按动作长短决定中间需要几音。亲密的小动作可以试柔起音的拨弦，靠轻重和疏密带出回应。按本片对白和环境确定音量、音色与尾音长度。
- 试听从揭示前一句对白或一个动作开始。同一剪点连看原声、短乐句，以及有意义时的单音版本；保持对白和环境一致，让候选的最响乐句听起来接近。可另附只循环结尾的快速对照，判断入乐时机用带前情的片段。
- 用户选中后，在现有声音记录中注明选中版本、适用段落、入点、落音和余音结束帧，沿用该选择。正式混音后复听同一窗口，尤其核对总线处理后对白、快门等前景与乐句的相对音量。

### 按风格取声音

已选风格时，在[99 支样片声音索引](../assets/sfx/atlas/index.html)按中文名称、动作或材质试听；自动选材用[轻量目录](../assets/sfx/atlas/index.json)的 localStyle 对应本 Skill 风格 ID。每条记录提供 file（相对于索引）、source、license 和 sha256。根据本镜的材质和情绪取舍，可以跨风格选用。只有需要追溯、改音色或重建时才读该样片的 sourceRecord，其中有原始 CREDITS 和音频制作代码。单片代表声与完整配乐、TTS 及用到的外部资产分别核对许可。选中后复制到项目、按原素材锁登记并绑到声音事件。

### 先试听本地拟音

卡扣、落桌、玩偶单步、闷响、掠风、弹出和提示铃适合微缩动作、界面及转场；铺纸、刻刀、金属轻碰、金属落地连响和远风适合手作、道具特写及空镜。黑板样片中 Tomproberts 的 41.69 秒 CC0 粉笔实录也已收录，按板书动作截取所需长度。按画面材质与远近挑选。[逐条试听](../assets/sfx/index.html) · [ID、文件、来源、示例事件和 SHA256](../assets/sfx/catalog.json)

直接从 Skill 的 `assets/sfx/clips/` 将选中的音频复制到工程 `audio/`。在 assets.json 中填工程相对路径、目录里的 sourceUrl、单条许可（程序拟音标明原作者与 MIT 代码来源，粉笔实录为 Tomproberts、CC0-1.0）和本镜 useBasis，使用程序拟音时随工程保留[许可](../assets/sfx/LICENSE.txt)。已有锁定文件的替换走素材候选和 diff；首次入片与其他轨一起 seal。将此轨的 startEvent 设为分镜事件，例如金属首次触地用 metal-drop；该条已含随后几次弹跳，避免叠加第二个落地声。

预制轨可直接混音。维护者需要重建时，在有 NumPy、SciPy 的环境从 Skill 根目录运行 `python3 assets/sfx/rebuild.py /tmp/new-foley-bank`，目标须为空。固定版本和每条种子留在目录中，本次生成使用 NumPy 1.25.2、SciPy 1.11.4。

### 可检索的公开来源

| 用途 | 到哪里找 | 入片与交付 |
|---|---|---|
| 街景、交通、器物、脚步 | [Freesound](https://freesound.org/help/faq/) | 核实每条录音的作者、原页及具体许可。CC0 或可履行署名的 CC BY 可作候选；含 NC 的条目排除商用。 |
| 已写好的配乐 | [Incompetech](https://incompetech.com/music/royalty-free/licenses/) | 免费授权要求署名，保存该曲生成的署名文本并放入实际交付。 |
| 面向成片的现成拟音 | [Mixkit 音效许可](https://mixkit.co/license/modal/sfxFree/) | 可用于符合条款的成片；开源模板、工具及源文件交付中排除这类原始音效。 |
| 城市或地方素材 | [地点声音](location-sound.md) | 优先核对实录地点与季节，缺证据的通用街声按通用氛围使用。 |

每条入片素材按[素材审阅](material-review.md)登记来源、许可和使用依据。衍生配乐保留作曲方式、采样库来源与许可；公开源码需可分发时，选可随包再分发的素材或可复现的原创合成脚本。免费试听本身不足以确定使用权。

### 试听与音量

先在对白或动作最密的一段定前景，再逐条加环境和音乐。从低音量试听关键字或短促动作声是否仍能辨认。需要让位时，设退下、保持和恢复节点；用前后两个节点控制渐变，保留自然尾音。四帧审阅时，有关键声画同步的项目附一个覆盖动作前后的有声片段，沿用原确认节点。最终编码后以实际 MP4 复听同一段，分别记录对白可懂度、拟音落点、背景是否遮挡以及有无突兀抽吸。总线响度或峰值只能说明电平。

### 动作拟音听成杂声时

从用户实际播放的版本定位。若是节选，先用剪辑入出点把「试剪第几秒」换回母带时码，列出该窗口正在响的轨及其声源。单听可疑轨，再在整段中静音、恢复这条轨，区分物件摩擦、风声、录音底噪和切点杂音。

- 给接触型拟音标出发声动作与结束动作，例如笔尖触纸、行笔、抬起。在分镜音效栏同时写入点和退点。以实际可听瞬态对上画面，用已有 `startEvent` 和 `gainEnvelope` 安排收声。声源尚在画外但能被观众理解时，可以提前入声。
- 同种噪声质感连续出现时，逐处问本镜新增了哪个发声动作。递出一张已经画好的纸，可以只留纸响；切到画作特写可以留白。对白附近先听清字头和字尾，再决定环境声退多少、何时回来。
- 用同画面、同剪点、同播放音量对听改前改后，连听问题段前后和邻近对白。比较实际交付文件同一窗口的电平，记录文件、时码、声源、改法和听感；缺少试听条件时记录测量与待听项。画面流复制时可核对解码帧一致。获批成片的换轨依[纯音轨修订](audio-revision.md)执行，未获批试剪沿用当前四帧流程。

## 通用管线字段

没有 rhythm / loop 的旧 film.json 保持原输出字段与时间语义。新增字段只编译节奏和审查信息，不选择画风、不改变旁白、不自动生成动作。修改这些代码/节奏配置需重锁时间轴和渲染；素材未变不重复确认。

```json
{
  "rhythm": {
    "bpm": 120,
    "offsetSeconds": 0,
    "beatsPerBar": 4,
    "basis": "用户提供的 120 BPM；已核对首重拍位于全片 0 秒",
    "audioFile": "audio/music.wav",
    "events": [
      {"id": "press", "beat": 2, "action": "光标按下按钮", "sceneId": "opening"},
      {"id": "expand", "beat": 4, "action": "同一容器展开为结果面板"},
      {"id": "settle", "beat": 6, "action": "面板停稳，音乐恢复"}
    ]
  },
  "audioTracks": [
    {"file": "audio/music.wav", "gain": 0.15, "gainEnvelope": [
      {"event": "press", "db": -8}, {"event": "expand", "db": -8}, {"event": "settle", "db": 0}
    ]},
    {"file": "audio/click.wav", "startEvent": "press", "gain": 0.4}
  ],
  "loop": false
}
```

这是 film.json 的可选片段，仍须有完整的 schema、画幅和 scenes；示例事件必须落在实际片长及 opening 镜头内。文件先登记资产并 seal，按原 timeline --lock → mix → preview → render → finish 流程执行。

- 拍号从 0 开始。BPM 每个拍点从绝对时间单独量化到最近整数帧（半帧向上），不累计已舍入拍长。offsetSeconds 是**全片时间**，已包含音乐进入点；不额外加 audioTracks.startSeconds。
- 变速/人工核对网格用 `"beatTimesSeconds": [0.15, 0.66, 1.18, 1.71]` 替代 bpm 和 offsetSeconds，不允许两种来源同时填写。时间点严格递增且落在 [0,totalFrames) 内，不允许不同拍点落到同一帧。
- rhythm.basis 必填，说明用户提供/人工设计/分析后核对；不提供自动音频测拍或正确性认证。与实际音乐关联时填 audioFile，必须引用 audioTracks 内素材，受原哈希与审阅约束。无配乐的设计节奏可省略 audioFile。
- events 为关键动作提示，不是动作引擎。id 唯一，action 必填；可填 sceneId 检查事件是否仍在指定镜头。生成代码读取 `timeline.rhythm.events` 的 frame，不能另造一套舍入规则。
- 音轨 startEvent、startBeat、startSeconds 三选一；前两者共用量化帧。画面从 drawScene 收到的全片 frame 减去 timeline.rhythm.events 中同名节点的 frame，即可用负值画准备动作、零画接触、正值画反应。
- gain 是音轨基础线性倍率；可选 gainEnvelope 的 db 是在此基础上的相对衰减。未填时保持整轨电平，填写时从轨首 0 dB 向首节点渐变（轨首有节点则直接取该值），节点间按 dB 线性插值，末值保持到轨尾。恢复基础音量用 0 dB。这是按事件编排的让位，需按实际素材试听。
-需要细分拍时提供更细的时间点网格；当前事件不接受小数拍号。
- 拍点越界、非法输入、音效超片尾均报错，不自动截断音乐或旁白。BPM 自动网格只生成片内拍点；引用片外 beat 会失败。更改镜头后复核事件与音乐关系。
- rhythm/loop 均写入 timeline 并由 filmSha256/时间轴过期检查约束。init 的工具副本需要同步升级 pipeline.py 和 render.cjs；原 asset_review.py、voice.py 保留在同目录。

预览继续包含每镜首中尾与字幕中点，额外抽取最多 64 个均匀覆盖全片的拍点，以及**每个**事件前/当/后帧。报告 `previewCoverage` 列出实际帧、总拍数/抽样拍数，长片不能冒称看完每拍；`preview/index.html` 汇总本次抽帧，旧 PNG 不列入本次索引。

`loop: true` 额外抽取片头/片尾连续三帧，并标 `sampled-needs-motion-and-audio-review`。不改变播放方式或导出长度，不调用区间外的第 N 帧，也不自动认定无缝；按制作类型说明人工检查接缝。

`previewPerformance` 保存实际截图调用数与耗时，以及全片截图成本粗估；其范围不含浏览器启动、完整编码与混音。它不是硬性时限或性能保证，shader、多重曝光等改动后必须重新测量。




四帧确认与最终编码验收沿[制作契约](production.md)和[四帧审阅](preview-review.md)，事件抽样不代替用户确认。
