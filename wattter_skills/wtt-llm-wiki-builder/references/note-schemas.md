# Note Schemas — 通用笔记卡字段与模板

> **何时用**：当一张卡片不属于 kp/case/model/concept 时，归到 `wiki/notes/`。本文件定义通用 note 卡片的字段、模板、与 kp/case/model/concept 的边界。

---

## 何时用 note 类型

| 内容 | 用哪种卡片 | 理由 |
|:---|:---|:---|
| 课程里可讲授的知识点 | **kp** | 有 module、讲次、领域，结构化 |
| 真实业务场景 / 故事 | **case** | 有 industry/scenario/outcome |
| 思维模型 / 决策框架 | **model** | 有 origin，可被多场景复用 |
| 跨卡片共享的抽象概念 | **concept** | 有 appears_in |
| 个人思考 / 反思 | **note** | 主观、非结构化、跨主题 |
| 会议记录 / 聊天记录 | **note** | 时序、非讲授单元 |
| 问题清单 / 待澄清问题 | **note** | 待跟进，不是确定知识 |
| 观察 / 摘录 / 引用 | **note** | 素材性质，不上升为结构化卡片 |
| 个人日记 / 灵感 | **note** | 时间序列、主题分散 |

> **判别口诀**：能用 5 分钟给别人讲明白 → 上升为 kp；不能讲明白但能引用 → 留作 note。

## 卡片目录约定

```
wiki/notes/
├── {note_type}/                 # 按类型分（可选）
│   ├── {YYYY-MM-DD}-{简称}.md   # 个人笔记语境：日期前缀便于排序
│   └── {source}-{简称}.md       # 知识库/综合语境：来源前缀
├── {topic}/                     # 按主题分（可选，与类型目录二选一）
│   └── ...
├── {project}/                   # 按项目分（个人笔记语境的常用切法）
│   └── ...
└── _topic-summary.md            # 主题/项目概要（下划线前缀排首位）
```

> **二选一**：建议优先按 `note_type/` 分（检索时"找所有反思"更常用），或按 `{project}/` 分（个人笔记语境下"找某项目相关"更常用）。混用会增加检索噪音。

---

## Frontmatter 必填字段

```yaml
---
note_name: MECE 的局限             # 唯一短名（与文件名一致更稳）
type: note                        # 固定值
note_type: 反思                     # 必填（见下表）
topic: 方法论                       # 必填（主题/项目名）
date: 2026-08-20                    # 必填（笔记发生日期）
source_marking: [已提取]            # 必填（[已提取] 或 [AI补全]）
tags: [mece, 方法论, 反思]          # 可选（细粒度标签）
related:                           # 可选（关联卡片，宽松即可）
  - "[[MECE原则]]"
  - "[[2026-08-15-读《金字塔原理》]]"
source_files:                      # 可选（来自哪份原始资料）
  - raw/transcripts/2026-08-20-meeting.md
last_compiled: 2026-08-20           # 可选（增量编译用）
confidence: medium                 # 可选（仅 [AI补全] 时填）
---
```

## note_type 类型表

| 类型 | 定义 | 典型场景 | 强制字段 |
|:---|:---|:---|:---|
| **摘录** | 从原始资料摘出的关键段落，不做改写 | 读书笔记 / 文章摘录 / 他人原话 | `source_files` 必填 |
| **反思** | 对某个观点/事件的个人反思 | "读完 X 后我的想法" | `topic` 必填 |
| **会议** | 会议记录 / 多人讨论 | 周会 / 客户访谈 / 朋友聊天 | `date` + 参与者可选 |
| **观察** | 对现象的观察记录，不上升为结论 | 产品体验 / 用户行为 / 现象描述 | `topic` 必填 |
| **问题清单** | 待澄清的问题或决策项 | "我还没想清楚的事" | — |
| **日记** | 个人日常记录 | 心情 / 当日复盘 | `date` 必填 |
| **引用** | 别人的话 / 金句 | 名人名言 / 书摘 / 推文 | `source_files` 必填 |
| **思考** | 跨主题的开放性思考 | "我对 X 的看法" | `topic` 必填 |
| **事件** | 已发生事件的记录 | 项目里程碑 / 个人事件 | `date` 必填 |
| **临时** | 临时记录，尚未分类 | 突然的想法 / 待整理 | — |

> **新增类型**：用户可自由定义新 note_type，但建议先用上表 10 种之一。检索时用 `rg 'note_type: 反思' wiki/notes/` 跨目录查。

## 卡片正文结构（参考，不强制）

note 卡片不像 kp/case 那样需要六段，**结构更松散**：

```markdown
> **一句话**：MECE 原则在快速变化的问题域里反而是负担。

## 背景
（什么时候、为什么想到这个）

## 关键内容
（核心想法，分段或列表均可）

## 待跟进
（还没想清楚的问题，链接到对应的"问题清单"笔记）

## 关联
- [[MECE原则]] — 被反思的对象
- [[2026-08-15-读《金字塔原理》]] — 触发本次反思的源头
```

> **不强求结构**：note 是 wiki 里最自由的卡片类型。能写就写完整，没想清楚就留空白字段。

## 与其他卡片类型的转换

| 场景 | 转换 |
|:---|:---|
| 一条 note 后来整理成可讲授的知识点 | 复制内容到 `wiki/kps/`，原 note 改为 `related: "[[新知识点]]"`，并标 `superseded_by: "[[新知识点]]"` |
| 一条 note 触发了一个 case 整理 | 在 case 卡 `related_notes` 里引用该 note |
| 多条 note 主题重复 | 合并到 `wiki/notes/{topic}/_topic-summary.md`，原 note 留 `merged_into` 字段 |
| 一条 note 上升为概念 | 抽到 `wiki/concepts/`，原 note 改为引用 |

> **不要让 note 留在主线**：note 的价值在于"留个念想"，但不应该长期阻塞主线。如果反复引用某 note，应上升为 kp/case/model/concept。

## 检索与索引

note 卡片的检索**主要靠 frontmatter 字段**，不靠正文（正文太自由）：

```bash
# 按时间
rg 'date: 2026-08' wiki/notes/

# 按类型
rg 'note_type: 反思' wiki/notes/

# 按主题
rg 'topic: 方法论' wiki/notes/

# 按关联
rg 'related: "\[\[MECE' wiki/notes/

# 全文搜索（兜底）
rg 'MECE' wiki/notes/ -l
```

`wiki/indexes/index.md` 在个人笔记语境下的段（见 `query-entries.md`）就是 note 检索的主入口。
