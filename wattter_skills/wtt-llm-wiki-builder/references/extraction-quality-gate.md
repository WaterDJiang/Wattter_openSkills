# Extraction Quality Gate — 可选深度萃取的质量门

> **使用方式**：在 Compile 模式"第一至十步"基础上，按需启用的**深度萃取模式**。用户说"严格筛选"/"高质量萃取"/"避免水卡"/"宁缺毋滥"时启用；默认轻量流程不走这里。
>
> **目的**：从 cangjie-skill 的 RIA-TV++ 方法论里**只借三样东西**（不搬整套流程）：
> 1. 强制**原文出处**（每张卡片要能追到原始资料的某段原文）
> 2. **三重验证**作为可选质量门（V1 跨域 / V2 预测力 / V3 独特性）
> 3. 每张卡片补一个**边界反场景段**（什么时候不要用这张卡片）

---

## 何时启用

默认情况走 SKILL.md 主流程的"第一至十步"（轻量），就够了。**只在以下场景启用本质量门**：

| 用户信号 | 启用强度 |
|---|---|
| "严格筛选 / 高质量萃取 / 宁缺毋滥" | 完整三重验证 + 原文出处 + 边界反场景 |
| "避免水卡 / 不要金句卡" | 仅启用 V3 独特性 + 边界反场景 |
| "卡片要能追到原文" | 仅启用原文出处规范 |
| 增量合并时已有冲突（同名/同义） | 仅启用 V1 跨域（判断"是否真的同义"） |

不在这些信号内 → 不启用，主流程的 `source_marking: [已提取]/[AI补全]` 已够用。

---

## 三样精华的落地细则

### 1. 原文出处（强制 — 让卡片可回溯）

#### 适用场景

启用本质量门时，每张卡片都要有原文出处，不只是 `source_marking: [已提取]`。

#### 必填字段（在卡片 frontmatter 加一个 `source_quote`）

```yaml
---
kp_name: 逆向思维
...
source_marking: [已提取]
source_quote: |              # 原文引用 ≤150 字（英文 ≤100 词）
  "反过来想，总是反过来想..."
source_chapter: 第三讲        # 章节/讲次/页码/时间戳
source_files:                # 原始资料路径（多份时填多行）
  - raw/transcripts/第03讲.md
---
```

#### 与现有 `source_marking` 的关系

- `source_marking: [已提取]` = 标注"这段话是从资料里直接提取的"
- `source_quote` = 标注"具体是哪段话、长什么样"
- 两者并存：前者回答"来源类型"，后者回答"具体段落"

#### 课程语境特化

课程语境的 R 段本身就是"原文引用 + 四点三线"，所以课程卡片天然有原文出处。本字段主要用于案例 / 模型 / 概念语境——它们之前只有 `source_marking`，缺原文。

### 2. 三重验证（可选 — 筛掉金句/常识/单点佐证）

#### V1 — 跨域验证

**问题**：这个单元在资料中**至少 2 个独立的语境**下有佐证吗？

- "独立"含义：不是同一案例换个说法，而是不同章节 / 不同对象 / 不同结论都在讲同一个道理
- **通过**：在投资决策 / 工程设计 / 教学方法 三个独立场景中都出现 → 通过
- **不通过**：某个漂亮句子只在一章里出现过一次 → 降级为金句 example 或素材外提

#### V2 — 预测力测试

**问题**：能用这个单元，推导出资料里没明说的某个问题的答案吗？

- 自己设计一个资料里没直接讨论过的场景，尝试用这个方法论分析它
- **通过**：能得出有意义、非平庸的结论 → 通过
- **不通过**：只能得出"努力就会成功"之类的废话 → 降级

#### V3 — 独特性检验（最常启用）

**问题**：这个单元是否是"任何聪明人都会说的常识"？

- 把讲者名字抹掉，领域无关的聪明人也能说出来 → 不通过
- **通过示例**：段永平的"stop doing list"——主动列出不做什么，反常识 → 通过
- **不通过示例**："要尊重时间"——太常识，不需要卡片承载 → 降级

#### 三项验证的启用方式

- **全部启用**：用户说"严格筛选"时
- **只启用 V3**：用户说"避免水卡"/"不要常识"时（这是最常用的单项）
- **全部不启用**：用户没要求时，走主流程的轻量筛选

#### 通过率预期

| 资料类型 | 通过率预期 |
|---|---|
| 方法论密集（课程 / 方法论书） | 30–50% |
| 案例故事密集（传记 / 创业史） | 10–20% |
| 散文随笔类 | 5–10% |

通过率 <5% 或 >80% 都要警惕：extractor 质量差 / 验证标准太松。

#### 淘汰的去向

未通过的不丢弃，写入 `raw/candidates/rejected/{id}.md`，附原因（审计价值，可被用户事后捞回）。或者降级为：

- 素材外提到 `materials/`
- 金句 example 附在某张卡片的 A1 段
- 概念卡但不加 `[已提取]` 标记

### 3. 边界反场景（让卡片不被乱引用）

#### 适用场景

启用本质量门时，每张卡片要补一段"什么时候不要用"。

#### 加在哪里

在卡片 L3 层（深读用）补一段 `## 边界反场景`：

```markdown
## 边界反场景

以下情况不应使用本卡片：

- 用户在做紧急决策（10 分钟内必须拍板）—— 本卡片的多步推理成本太高
- 纯信息查询类问题（"什么是 X"）—— 不需要决策框架
- 与 "[[决策清单]]" 类方法论容易混淆 —— 本卡片是"反推失败"，决策清单是"穷举选项"

来自资料的警告：
- 讲者在第 5 讲明确说过："逆向思维不是'消极悲观'，不要把它当成'凡事只想坏的一面'"

来自资料未提及的盲点（AI 补全）：
- 资料写于 1990 年代美国投资语境，在中国 2020 年代的创业场景下可能过度强调"避免失败"而错失"快速试错"的机会
```

#### 三类边界来源

| 来源 | 含义 | 标注 |
|---|---|---|
| **资料内警告** | 讲者在资料中亲自说过的反场景 | `[已提取]` |
| **跨卡片混淆** | 和 wiki 内其他卡片容易混用 | `[[其他卡片]]` |
| **AI 补全盲点** | 资料未提但实践中容易踩的坑 | `[AI补全]` |

## 与主流程的衔接（什么时候插入）

启用本质量门时，把下面三步插入到 SKILL.md "第一至十步"的合适位置：

| 插入位置 | 在第几步之后插入 | 做什么 |
|---|---|---|
| **强制原文出处** | 第 4 步（四点萃取）后 / 案例模型步骤后 | 每张卡片加 `source_quote` + `source_chapter` 字段 |
| **三重验证** | 第十步（标记来源）之前 | 跑 V1/V2/V3，通过的进卡片，淘汰的进 `rejected/` |
| **边界反场景** | 第八步（卡片关联）后 / 第十二步（log/index）前 | 补 L3 的 `## 边界反场景` 段 |

插入后第 4.5/5/8/10/12 步的标题不变，只在内部多加一个动作。

## 不在本质量门做的事

为了不把 wiki-builder 变成 cangjie-skill 的克隆，本质量门**明确不做**：

- � 五阶段管线（阶段 0/1/1.5/2/3）—— wiki-builder 的轻量十步已够，不搬整套
- ❌ 五类并行提取器（framework/principle/case/counter-example/glossary）—— wiki-builder 按语境选模板，不需要五路并行
- ❌ RIA++ 六段构造（R/I/A1/A2/E/B）—— wiki 卡片的 schema 已有自己的字段体系，不替换
- ❌ PIPELINE_STATE 断点续跑—— wiki 自身的 `log.md` 已承担审计 + 续跑职责
- ❌ Zettelkasten 五类引用关系（depends_on / contrasts_with / combines_with / derived_from / refutes）—— wiki 现有的"前置依赖 / 互补 / 跨域类比 / 教学迁移"四类已够

> 这五点是从 cangjie-skill 评估后**不迁移**的部分。两个 skill 的产物形态不同（SKILL.md vs frontmatter 卡片），不强行对齐。
