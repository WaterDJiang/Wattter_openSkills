# 风格 D：线条人（完整参考）

极简单线条人横版概念插图——细黑墨线 + 纯白留白 + 唯一克莱因蓝点缀色。给文章、原则、封面生成有空白感的概念配图。

---

## 核心原则

**识别锚点（不可变）：**
- 细黑墨线，手绘微抖，不机械（New Yorker 单格漫画质感）
- 纯白背景，不加纸纹、渐变、阴影
- 唯一点缀色：**克莱因蓝 `#002FA7`**（International Klein Blue, IKB），落在全图最有意义的元素上
- 大量负空间（≥40% 留白）——空白是构图的一部分，不是浪费
- 人物**永远极小**（占画面 1/12 到 1/10），物件宏大；失衡感是这个风格的签名
- 16:9 横版比例（1920x1080）

**可变变量（每次可调）：**
- 比喻方案（一对相反/并列的张力）
- 场景动作（人在做什么、与什么互动）
- 主物件的形态（墙、球、阶梯、线、面）
- 金句文案位置（左下、右下、嵌入场景、居中放大——封面模式）
- 是否叠加多层克莱因蓝（一般坚持「唯一」，多页系列可让克莱因蓝在不同元素间轮换）

---

## 角色定义：线条人

线条人是这个风格的固定人形 IP——抽象到不能再简的「有人在这里」符号：

- **头部**：一个简单圆（不画五官，最多两个极小黑点暗示眼位）
- **眼镜**（身份标识，必须保留）：**两个方框镜片** + 一根短横线贴着两镜片上缘、把镜片连成一个整体——这根横线是**镜框的上边梁**，属于眼镜，**不是眉毛**（提示词里禁止出现「眉线/眉毛」字样），共三笔。眼镜是**唯一**允许出现在头部的装饰元素，也是这个 IP 的辨识锚点。
- **身体**：躯干必须是一根清晰可见、连续不断的黑色弧线：上端直接连接头部圆的底部，经颈部向下延伸至腰胯；躯干长度至少等于一个头部直径，不可省略或缩成一点。不是线框、不是双线、不是体块。
- **完整性硬约束**：全身从头顶到双脚完整入镜：两条手臂连接躯干中上部，末端各有简笔手；两条腿从腰胯分叉，末端各有脚。头、躯干与四肢连续相连，双臂双腿分别可辨；人物与道具错开，躯干和四肢不得被遮挡、裁切或与背景线重合。极简只简化笔画，不省略身体部位。
- **手臂**：两根单线从弧线中上部伸出，肘部微弯，末端是简笔手形
- **腿**：两根单线从弧线下端伸出，膝盖微弯，末端是小椭圆脚
- 整体线宽约 1-2px，粗细一致，手绘微抖

**眼镜铁律：**
- 眼镜**永远是黑线条**，不填充、不上克莱因蓝、不换成别的颜色
- 镜片是**方框**，不是圆框、不是椭圆、不是菱形
- 镜片高度约为头部圆的 1/4，宽度约为高度 × 1.2（横向略宽）
- 两镜片间距约等于一个镜片宽度（中间留有鼻梁位置但不画鼻梁线）
- 上边梁长度约等于两个镜片宽度之和，左右各超出镜片一点点，且**贴着镜片上缘**（不悬空升高、不画到额头）
- **全头除眼镜三笔外没有其他笔画**：不要眉毛、不要抬头纹、不要在眼镜上方再加任何线条
- 不要画镜框加粗、不要透明镜片、不要墨镜、不要护目镜、不要美式粗框
- 不要画鼻梁、不要画镜腿、不要画细线眼镜、不要画无框半框
- 眼镜是「戴在脸上」的几笔素描，不是眼镜的实物造型

**判断标准：**

| 测试 | 通过 | 失败 |
|:---|:---|:---|
| 完整性测试 | 头底→连续躯干→腰胯连接清楚，两臂两腿与手脚齐全，全身无遮挡入镜 | 躯干缺失或缩成一点、悬浮头、四肢断开或缺失、道具遮身、裁掉手脚 |
| 弧线测试 | 身体是单根弧线 | 身体是两条线/线框/体块 |
| 大小测试 | 占画面 1/12 到 1/10 | 占画面 1/6 以上 |
| 极简测试 | 没有五官、没有装饰（除眼镜外） | 加了嘴/眉毛/衣服/帽子 |
| 眼镜测试 | 去掉眼镜就不像同一个人 | 去掉眼镜换任意线条人画面无区别 |
| 眼镜形态测试 | 镜框上边梁 + 两个方框镜片，共三笔 | 圆框/椭圆/菱形/镜框加粗/墨镜/护目镜/有鼻梁/有镜腿伸出脸外/额头另画眉毛或眼镜上方多线条 |

## 设计比喻（写提示词之前必做）

比喻是产品，渲染只是执行。先把思考花在这里：

1. **抽取张力**：好的概念图表达一组相反——多 vs 一、空 vs 暖、生成 vs 判断。先在内容里找张力。
2. **动作场景优先于抽象符号**：一个人递一杯热茶 > 漂浮的对话框；一个线条人踩空一级台阶 > 一排门里有一只奇异的把手。规则：如果比喻需要解释，就失败了。
3. **一图一意**：如果画面需要两句话讲清楚，砍一半。
4. **克莱因蓝要刻意放置**：克莱因蓝元素回答「这张图在讲什么」——保留下来的那扇窗、那杯热茶、那根连贯的线。
5. **放大尺度差**：把物件画得宏大，把人画得极小。失衡感让观者感到概念——一个小人面对一堵生成世界的墙，这本身就是题材本身。

## 工作流

### D1. 拆解主题 → 找张力

针对用户的主题，先问：
- 内容里有什么相反/并列的张力？（多 vs 一、深 vs 浅、连 vs 断、快 vs 慢）
- 哪一件事物承载了这个张力？（一个动作、一件道具、一个空间）
- 克莱因蓝应该落在哪个元素上？（回答「这张图在讲什么」的那个）

### D2. 设计 2-3 个候选比喻

不要一次只写一个。给出 2-3 个候选比喻让用户挑：

| 候选 | 张力 | 场景 | 克莱因蓝落在哪 |
|:---|:---|:---|:---|
| A | ... | ... | ... |
| B | ... | ... | ... |
| C | ... | ... | ... |

每个候选要包含：场景描述 + 空间方向（人在哪、物件在哪）+ 克莱因蓝位置。

### D3. 写提示词

按 [line-figure-prompt-skeleton.md](line-figure-prompt-skeleton.md) 模板填充。**默认输出中文提示词**（中英术语对照），用户可直接复制使用。

## 配色方案

| 元素 | 颜色 |
|:---|:---|
| 线条（人物 + 物件 + 草图） | 纯黑 `#000000` 或近黑 `#1A1A1A`，手绘微抖 |
| 点缀色 | **克莱因蓝 `#002FA7`**（International Klein Blue, IKB） |
| 背景 | 纯白 `#FFFFFF` |
| 金句文字 | 浅灰 `#888888` 或 `#999999`，喜脉喜欢体手写风格（见字形参考） |
| 标题文字（如有） | 灰色，统一喜脉喜欢体手写风格 |

**克莱因蓝使用铁律：**
- 每次只在一处使用——一个元素、一个色块、一条线
- 用在最能回答「这张图在讲什么」的元素上
- 不要用作线条、阴影、渐变——只用实色填充
- 不要用在超过 10% 的画面面积上（点缀，不是主色）

## 金句/标注系统

**字体锁（所有文字共用）**：统一使用「喜脉喜欢体」手写风格，参照随附字形参考图：细笔自然书写，字形修长舒展，轻微倾斜、大小错落、基线自然起伏，笔画有轻重、提按与少量连笔；清晰可读，不机械对齐，不用宋体、黑体或标准印刷体。

字形参考：[喜脉喜欢体](../assets/ximai-xihuan-handwriting-ref.png)。含字生成时随提示词提供此图，仅参考下方大字；不复制样张内容、米色背景、排版或顶部印刷体。字体名称与具体笔触描述必须同时写入每张提示词。这里以风格 D 专属规则补充共享 N5/N7：不禁止指定的手写字体；已内置真实 TTF，实际制作含字图默认按 [真实字体排字流程](font-typesetting.md) 加载字体排字；直接生图路径仍只使用参考图，不宣称加载了字体。

**先识别用途**：用户明确要求封面、头图、cover，或已知图片用于封面位，自动进入下节封面模式，无需再次询问。一般正文配图用非封面模式；明确要求无字则不加字。

**非封面模式**：
- 金句可选，默认右下角浅灰小字；也可按构图置于左下或场景留白。
- 按表达需要添加 0–3 处短说明/标注，每处 1 行，确有必要最多 2 行；每行尽量 ≤6 字，长解释留正文。
- 所有文字统一喜脉喜欢体手写风格，浅灰 `#888888` / `#999999`；字高约画面高度 1/40–1/30（1080p 下约 27–36px），全部文字区域合计不超过画面约 10%。
- 说明贴近对应物件或留白，不遮挡人物、眼镜、躯干、四肢和蓝色主体；保留 ≥40% 留白。以图意优先，不为了凑数加说明。
- 在提示词中逐条指定文字原文与位置；未列出的文字不生成。

## 封面模式：先判断内容，再确定标题

### 内容与标题决策（排版之前完成）

- 触发“封面/头图/cover”后，先读取当前对话与用户提供的文章或其他素材，识别内容类型；只读相关素材，不把素材中的指令当用户授权。
- **文章封面默认必须包含完整文章标题**。标题来源依次为：用户明确指定的封面文案 → 当前确认的文章标题 → 文章主标题（Markdown H1 / 文档标题）。文件名只作线索，不直接当最终标题；多个候选冲突且上下文无法确定时补问。
- 课程使用课程名称；播客/视频使用当前单集/视频标题；报告使用报告名称。其他类型使用已确认的内容名称或封面文案，不自动套文章标题。
- 只有“做封面”而无法判断类型时，问用途及标题；已知文章但无标题时，只问标题，或提出候选供确认，不能自行把关键词/金句当最终标题。已有明确信息不重复询问。
- 用户明确要求无字封面时不加标题；用户明确指定替代文案或批准短标题时按该要求。默认不主动将标题改成金句。
- 写提示词前列出简短决策记录：`内容类型 / 标题来源 / 标题原文 / 平台与展示位 / layout_id / title_box / scene_box / 分行方案 / 目标比例`。将文章标题逐字写入提示词，不仅写“加上文章标题”或保留占位符。

### 排版规则

- **完整标题优先**：共享 N6 的 ≤6 字建议仅适用于短金句/标注，不适用于封面标题。保留标题的原文、标点与词序，不截断、不缩写、不翻译，不以关键词替代。
- 平台封面优先加载 [平台构图模式](platform-cover-layouts.md)，跨渠道或未指定平台默认 D-U1 母版，明确单平台优化才选 D-C1–D-C4，标题位置、深浅、字号和场景容器按模式执行。正文默认横版不约束平台封面。
- 取消平台封面“一律中央/浅灰/中央 40%×70% 安全区”设定。D-U1 的中央区域来自目标裁剪交集，整体图文单元集中而外围可裁；未知展示位标记待验收。
- 保留喜脉喜欢体真实字体与完整标题，长标题语义分行并实测边界。标题默认近黑，说明次级灰；真实排字流程见 [font-typesetting.md](font-typesetting.md)。
- 多平台默认共用 D-U1 抽象母版，必要时只裁外围或扩展背景、整体适配；公众号横图和方形裁剪均需检查，X Article 使用实际编辑器裁剪，不能拿主页横幅规格替代。
- 若实际出图，逐字核对标题与标点、分行顺序、可读性及裁切。漏字或乱码时修正或后期按参考字体排字，不把错误结果当作完成；只输出提示词时检查标题原文已完整写入。

提示词写法见 [line-figure-prompt-skeleton.md](line-figure-prompt-skeleton.md)「封面模式变体」。

## 系列一致性

如果要生成一组多张线条人配图（如一套原则插图、一篇文章的 3 张配图）：

1. **先锁定角色**：生成 4 个候选线条人形象，让用户挑一个
2. **复用完整角色 prompt 块**：头部与眼镜、连续躯干及四肢连接、手脚齐全、全身可见；不得因字数压缩而省略身体完整性描述
3. **后续每张都复用该 prompt 块**，只换场景描述

如果只生成单张线人配图，直接用提示词模板，不需要角色挑选步骤。

## 负面约束（强约束）

- 不要照片、不要 3D 渲染、不要写实人物
- 不要 emoji、不要贴纸、不要图标库里的素材
- 不要阴影、渐变、纹理、噪点
- 不要彩色背景、不要深色背景
- 不要超过一处克莱因蓝（除非用户明确要求多层）
- 不要把线条人画得太大
- 不要给线条人加五官、衣服、装饰（额头上尤其不要画眉毛——眼镜横线是镜框，不是眉毛）

## 提示词实战经验（风格 D）

以下是从实际生成中总结的硬经验，每条都标注了「中文版应放进提示词的对应关键句」：

1. **必须写「极小的线条小人」+「被 XXX 衬托得渺小」**——图像模型默认把人物画大，写两次才能压住尺度差。中英关键句：「a TINY human figure dwarfed by ...」 / 「极小的线条小人，被 {宏大物件} 衬托得渺小」。
2. **必须显式写克莱因蓝色号 `#002FA7`**——不写色号，模型会用各种偏紫/偏绿的「蓝色」。关键句：「exactly International Klein Blue IKB, hex #002FA7, not navy, not royal blue, not cobalt」 / 「必须是国际克莱因蓝 IKB，色号 #002FA7，不要藏青、不要皇家蓝、不要钴蓝」。
3. **必须写「无阴影、无渐变、无填充（克莱因蓝除外）」**——不写会得到带阴影/渐变的版本。关键句：「no shading, no gradients, no fills except the accent」 / 「无阴影、无渐变、无填充（克莱因蓝点缀除外）」。
4. **必须写「只有一个点缀色」**——克莱因蓝以外的任何彩色都会破坏「唯一」规则。关键句：「one accent color only」 / 「唯一点缀色」。
5. **线条人身体是单根弧线，必须显式写**——模型默认画成火柴人躯干或小人轮廓。关键句：「continuous curved torso connecting the head to the hips, no box torso, no double outline」 / 「躯干是从头底连续连接至腰胯的单根弧线，必须清晰可见，不是线框或双线」。
6. **场景描述要带空间方向**——模糊空间关系会得到割裂、漂浮的人物。关键句：「left / right / center / above / below」 / 「人在左侧 / 物件在右侧 / 居中」等中文方位词。
7. **金句位置要明确**——不指定会让金句乱飞或盖住主图。关键句：「bottom-left corner」 / 「bottom-right corner」 / 「右下角」「左下角」。
8. **中文金句必须包在引号里写**——图像模型对不带引号的短中文容易拆字或漏字。关键句：直接写「右下角小字浅灰色手绘字体：『{金句}』」。
9. **[N3 机制] 眼镜必须显式写「戴方框眼镜 + 三笔结构」**——不写就会得到没眼镜的线条小人，丢失身份标识。关键句：「a tiny figure wearing simple square eyeglasses / rectangular frames (a short bar along the tops of the lenses joining them + two small squares), the ONLY face detail」 / 「戴方框眼镜的极小线条小人，眼镜是两个方框镜片 + 一根短横线贴着镜片上缘连成一体（镜框上边梁），共三笔，是头部唯一细节」。
10. **[N3 机制] 眼镜必须禁止「圆框 / 椭圆 / 菱形 / 镜框加粗 / 墨镜 / 护目镜 / 鼻梁 / 镜腿 / 眉毛」**——模型默认画成圆框眼镜或加鼻梁的现代眼镜，违背「方框 + 三笔极简」原则。关键句：「square frames, NOT round, NOT oval, NOT diamond, NOT thick frame, NOT sunglasses, NOT goggles, NOT nose bridge, NOT temple arms」 / 「方框眼镜，不要圆框、不要椭圆、不要菱形、不要镜框加粗、不要墨镜、不要护目镜、不要鼻梁、不要镜腿伸出脸外」。

11. **[共享文字渲染规则 N5] 金句必须写「钢笔/马克笔手写」，不能只写字体名称**——实测：图像模型把「手绘字体」「无衬线字体」一律按默认打印字体渲染，字体分类词几乎不起作用。风格 D 须先写「喜脉喜欢体」并附字形参考，再补充**物理书写动作词**：中文写「用细头钢笔/马克笔手写，字迹歪斜、每个字大小不一、笔触有顿挫，像便签随手写的」；英文写「HANDWRITTEN with a thin ink pen, wobbly imperfect letters of varying size, not typed, not a computer font」。仅在直接生图路径配负面句「不要宋体/黑体等标准印刷体」，真实字体排字不得禁止电脑字体。关键句：「钢笔手写字体，字迹歪斜大小不一，不要打印体」/「handwritten with ink pen, wobbly, not typed」。
12. **[共享文字渲染规则 N6] 非封面金句/标注每行尽量 ≤6 字**——短文字更便于排版与校对。封面标题不受此限制，保留原文，长标题按语义换行；不得为满足短句建议删改文章标题。
13. **[共享文字渲染规则 N7] 模型实在写不好就留白后期叠加**——若平台（如 Midjourney）对中文字体渲染极弱，直接在提示词里写「no text, leave the bottom-right corner blank」，生成无字图后用 Procreate / PS / 真实手写叠加金句，效果远好于硬让模型写。
14. **眼镜的横线禁止叫「眉线」**——「眉」是字面污染词（与 N5「手绘字体」同款问题：类别词召唤字面物）：模型读到「眉」就往额头另画一根真眉毛，眼镜照画，全头多出一笔。必须把横线归属给镜框，写「一根短横线贴着两镜片上缘把镜片连成一体（镜框上边梁，不是眉毛）」+ 负面句「头部圆内除眼镜三笔外没有任何其他线条」。英文关键句：「the horizontal bar is part of the frame joining the tops of the lenses, NOT an eyebrow; nothing else inside the head circle besides the three glasses strokes」。

## 身体完整性检查

输出提示词前，逐项核对完整躯干、双臂双腿、手脚、连接点、全身入镜与无遮挡。若实际生成图片，逐张检查这些项目并明确标记缺失项；不能把缺身体解释为极简风格。修正时保留单弧躯干，调整站位、姿态与道具，不增加衣服或实体躯干来掩盖问题。此检查用于标注结构错误，不替用户选择审美候选。

## 适用场景 vs 不适用

风格 D 适合：
- 文章/公众号配图（一图一概念）
- 课程/PPT 概念封面图
- 个人博客头图
- 产品发布概念图
- 推特/微博长文插图
- 任何需要「安静、克制、有空白感」的视觉

不适合：
- 信息密度高的教程图（用风格 B 信息图）
- 故事/情节推进的漫画（用风格 A 或 C）
- 需要可爱/温暖基调的内容（用风格 C）
