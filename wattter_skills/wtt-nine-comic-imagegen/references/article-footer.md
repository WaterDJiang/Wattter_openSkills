# 公众号与 Twitter/X 文章文末配图

## 触发与范围

- 为微信公众号文章、Twitter/X Article 或用于这两个渠道的完整文章准备配图时，默认将 [个人介绍图](../assets/article-footer-profile.png) 作为最后一张配图，全文结尾之后单独成图。
- 不受当前生成风格限制；它是已确认的固定素材，不是生成候选，不需要再次询问采用哪张。用户明确取消或替换时按用户要求。
- 仅请求封面或单张示意图时，不拼入此图；普通 X 短帖/线程不自动追加。明确用于其他平台的版本不自动携带。多渠道共用稿只放一份，分平台交付时检查目标版本的文末顺序。

## 原图与交付

- 固定路径：`{SKILL_DIR}/assets/article-footer-profile.png`。保留原始像素、文字与比例，不重绘、不裁剪、不重新排字；不套用线条人单弧身体、喜脉喜欢体或封面核心区规则，不拿它作为生图角色参考。
- 为具体文章交付时，复制到该文章的 assets 目录，使用相对 Markdown 路径，不引用用户原始绝对路径或 skill 安装目录。保留源稿，按任务授权写入配图稿或交付副本。
- 在正文、结语及来源区之后加入独立图片段，后面不再放其他文章配图。例如文章与 assets 同级时：

```markdown
![Wattter 个人介绍](assets/article-footer-profile.png)
```

- 此素材默认在内容配图之外追加，清单写明“内容配图 N 张 + 文末介绍图 1 张”。若用户限定包含所有图片的总数，则在该总数内预留最后一张，不擅自超额。
- 仅输出提示词时，将此项列为“直接复用已有素材，无需生成”，附实际素材链接及文末放置说明；不把未修改的文章报告为已追加。

## 防重复与下游核验

- 先检查当前文末图片引用与文件内容；用文件哈希识别重命名的同图。已在文末则不重复追加；已在正文其他位置时，在本次可编辑的交付稿中移至文末，仅保留一次，不误删不同图片。
- 资产缺失时明确报告缺失路径，不生成替代人物图，也不静默省略。
- 配图清单将它列在最后。交给发布工具时，它是普通正文图片，不作封面或附件下载链接；仅有发布/草稿授权时才进行平台写入。
- 本地验收：复制文件存在、相对路径有效、完整比例、图像内容未变、最后一张且仅一次。平台验收：对应文章编辑器末尾实际显示此图；无法检查则标记待验证，不把本地文件存在当作平台完成。
