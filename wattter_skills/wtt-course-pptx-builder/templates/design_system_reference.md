# {project_name} - Design System

> **How to combine** the values locked in `spec_lock.md`. `spec_lock.md` locks *what* (colors / fonts / icons / image sources); this file locks *how* — frozen SVG skeleton fragments, decorative motifs, spacing tokens, and per-page-type layout shells. It is the "lightweight bespoke template" generated for this project so that 500 pages generated by parallel segment sessions stay visually coherent without each session re-inventing the chrome.
>
> **Consumed by**: segment agents in the parallel-execute workflow (see [`workflows/parallel-execute.md`](../workflows/parallel-execute.md)). Read once at segment start, alongside the anchor SVGs. Segment agents **copy fragments verbatim** rather than re-drawing them.
>
> **Produced by**: Strategist, when page count ≥ 60 (the parallel-mode threshold). Optional for smaller decks. Skeleton: this reference template.
>
> **Divergence rule**: `spec_lock.md` still wins on values (colors / fonts / sizes). This file wins on *composition* (how those values are arranged). If a fragment here uses a color not in `spec_lock.md`, fix the fragment, not the lock.

## I. Spacing Tokens

Named spacing values used across all pages. Segment agents reference these by name when positioning elements; `consistency_checker.py` validates SVG coordinates respect them (±2px tolerance).

| Token | Value (px) | Use |
| ----- | ---------- | --- |
| `--margin-page` | 60 | Page outer margin (left/right) |
| `--margin-page-y` | 50 | Page outer margin (top/bottom) |
| `--gap-card` | 24 | Gap between peer cards in a grid |
| `--gap-section` | 40 | Gap between major sections on a page |
| `--padding-card` | 20 | Inner padding of a card container |
| `--padding-content` | 32 | Inner padding of a content block |
| `--title-to-body` | 16 | Gap between page title and first content row |
| `--footer-offset` | 30 | Footer distance from bottom edge |

> Fill these from the locked `visual_style`'s spacing character. Dense decks lean 16–20px gaps; breathing decks 40–60px. Do not invent tokens beyond what the deck uses.

## II. SVG Skeleton Fragments

Frozen SVG snippets for recurring chrome. Segment agents **paste these verbatim** and only swap placeholder text / icons / images. Each fragment is a top-level `<g id="...">` so it doubles as an animation anchor (see `shared-standards.md` §4).

### II.1 Page Header

```xml
<g id="page-header">
  <text x="60" y="70" font-family="{{title_family}}" font-size="{{title_size}}" font-weight="bold" fill="{{primary}}">{{PAGE_TITLE}}</text>
  <rect x="60" y="86" width="56" height="4" fill="{{accent}}"/>
</g>
```

### II.2 Page Footer

```xml
<g id="page-footer">
  <line x1="60" y1="690" x2="1220" y2="690" stroke="{{border}}" stroke-width="1"/>
  <text x="60" y="708" font-family="{{body_family}}" font-size="12" fill="{{text_secondary}}">{{project_name}}</text>
  <text x="1220" y="708" text-anchor="end" font-family="{{body_family}}" font-size="12" fill="{{text_secondary}}">{{NN}}</text>
</g>
```

### II.3 Card Container

```xml
<g id="card-{{N}}">
  <rect x="{{x}}" y="{{y}}" width="{{w}}" height="{{h}}" rx="12" fill="{{bg}}" stroke="{{border}}" stroke-width="1"/>
  <!-- card content: icon + title + body, padded by --padding-card -->
</g>
```

> Shadow only when the card floats over a photo/colored panel (see `shared-standards.md` §6). On a flat white canvas, omit the filter.

### II.4 KPI Block

```xml
<g id="kpi-{{N}}">
  <text x="{{x}}" y="{{y}}" font-family="{{title_family}}" font-size="48" font-weight="bold" fill="{{primary}}">{{NUMBER}}</text>
  <text x="{{x}}" y="{{y+24}}" font-family="{{body_family}}" font-size="14" fill="{{text_secondary}}">{{LABEL}}</text>
</g>
```

### II.5 Section Divider

```xml
<g id="divider">
  <line x1="60" y1="{{y}}" x2="1220" y2="{{y}}" stroke="{{border}}" stroke-width="1" stroke-dasharray="2,2"/>
</g>
```

> Add more fragments only for chrome this deck genuinely repeats (e.g., a brand corner mark, a chapter number badge). Avoid fragment bloat — every fragment is one more thing a segment agent must place correctly.

## III. Decorative Motifs

Project-specific decorative elements that must recur across pages without drift. These are the motifs `consistency_checker.py --against-anchors` verifies for continuity (hash of `<path d=...>`).

### III.1 {Motif Name — e.g. "Brand corner mark"}

```xml
<g id="motif-corner-mark">
  <path d="M1180,40 L1220,40 L1220,80" fill="none" stroke="{{accent}}" stroke-width="3"/>
</g>
```

**Where used**: every content page, top-right corner. Not on cover/ending.

### III.2 {Motif Name — e.g. "Chapter badge"}

```xml
<g id="motif-chapter-badge">
  <circle cx="100" cy="100" r="48" fill="{{primary}}"/>
  <text x="100" y="112" text-anchor="middle" font-family="{{title_family}}" font-size="36" font-weight="bold" fill="{{bg}}">{{CHAPTER_NUM}}</text>
</g>
```

**Where used**: chapter opener pages only.

> List only motifs that are load-bearing for visual identity. If the deck has no signature decorative element, omit this section entirely (a minimalist Swiss deck may have none).

## IV. Layout Shells

Per-page-type structural skeletons. Each shell fixes the zones (header / content / footer placement) while leaving content free. Segment agents inherit the shell for the page's type, then fill content per `design_spec.md §IX`.

### IV.1 Cover Shell

```
+----------------------------------------------------+
|  (full-bleed background or motif)                 |
|                                                    |
|         {{COVER_TITLE}}                            |
|         {{SUBTITLE}}                               |
|                                                    |
|  {{DATE}}                          {{AUTHOR}}      |
+----------------------------------------------------+
```
- Rhythm: `anchor`
- Inherits: anchor page `01_cover.svg`

### IV.2 Chapter Opener Shell

```
+----------------------------------------------------+
|  [chapter badge]   {{CHAPTER_TITLE}}              |
|                                                    |
|  {{CHAPTER_INTRO_SENTENCE}}                        |
|                                                    |
+----------------------------------------------------+
```
- Rhythm: `anchor`
- Inherits: anchor page `02_chapter.svg`

### IV.3 Content (dense) Shell

```
+----------------------------------------------------+
| {{PAGE_TITLE}}                                     |
| ──                                                 |
| [content grid: cards / KPI / table / chart]        |
|                                                    |
+----------------------------------------------------+
| footer                                             |
+----------------------------------------------------+
```
- Rhythm: `dense`
- Card grid permitted (2-up / 3-up / 4-up per content weight)

### IV.4 Content (breathing) Shell

```
+----------------------------------------------------+
|                                                    |
|         {{SINGLE_HERO_ELEMENT}}                    |
|         {{ONE_LINE_INTERPRETATION}}                |
|                                                    |
+----------------------------------------------------+
```
- Rhythm: `breathing`
- **No multi-card grid** — `consistency_checker.py` flags >2 rounded rects on a breathing page

### IV.5 Ending Shell

```
+----------------------------------------------------+
|                                                    |
|         {{THANK_YOU / CTA}}                        |
|         {{CONTACT}}                                |
|                                                    |
+----------------------------------------------------+
```
- Rhythm: `anchor`
- Inherits: anchor page `04_ending.svg`

> Add shells only for page types this deck actually uses. A pure data briefing may drop the breathing shell; a narrative deck may add a "quote" shell.

## V. Anchor Page References

The 5–10 hand-written gold-standard pages that segment agents must align to. Generated by the main agent before parallel generation starts; frozen after human approval (see `parallel-execute.md` Step 1).

| Anchor Page | File | Page Type | Rhythm | Aligned-By |
| ----------- | ---- | --------- | ------ | ---------- |
| Cover | `svg_output/01_cover.svg` | cover | anchor | all `P<NN>` cover pages |
| Dense content representative | `svg_output/05_dense_repr.svg` | content-dense | dense | all dense content pages |
| Breathing representative | `svg_output/12_breathing_repr.svg` | content-breathing | breathing | all breathing pages |
| Chapter opener | `svg_output/20_chapter.svg` | chapter | anchor | all chapter pages |
| Ending | `svg_output/50_ending.svg` | ending | anchor | all ending pages |

**Segment agent protocol** (see `executor-base.md` §3 "large-scale parallel path"): at segment start, batch-Read this `design_system.md` + every anchor SVG listed here + `spec_lock.md` + the segment's `§IX` slice. Then generate each page by: (1) inheriting the matching shell, (2) pasting skeleton fragments verbatim, (3) filling content from `§IX`, (4) re-reading `spec_lock.md` per page for values.

> Anchors are **immutable** after approval. If a segment agent finds an anchor genuinely wrong, it surfaces a warning — it does not edit the anchor.

## VI. Consistency Checkpoint Summary

What `consistency_checker.py` validates against this file:

| Check | Source | Severity |
| ----- | ------ | -------- |
| Color set ⊆ `spec_lock.colors` | spec_lock | flag (score) |
| Font set ⊆ `spec_lock.typography` | spec_lock | flag (score) |
| Breathing page has ≤2 rounded rects | §IV.4 shell | flag (score) |
| Rhythm distribution not 100% breathing | spec_lock `page_rhythm` | warning |
| Anchor decor motifs recur on non-anchor pages | §III | info |
| Spacing tokens respected (±2px) | §I tokens | info (planned) |

> Threshold: a page failing >30% of applicable checks is flagged and sent to the repair loop (see `parallel-execute.md` Step 4).
