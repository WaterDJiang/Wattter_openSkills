# F：封面提示词与候选记录

先读[封面流程](style-f-cover.md)和[图文融合规则](cover-type-composition.md)。每张采用一个[方向](cover-style-catalog.json)，把其视觉、字形、图文关系、色彩和禁忌编入同一份本篇内容的提示词。以下为检查字段，具体语句连贯描述画面，交付前替换变量并删除不适用段落。

## 单张候选的提示词

```text
制作一张独立封面，不生成拼图或带选项标签的比较板。
内容类型与用途：{本次内容及展示位}。
请求比例：{requested_ratio}；本次实际生成比例：{generation_ratio}；目标尺寸：{工具可用尺寸或明确说明由工具确定}。

主题理解：{一至三句必要摘要；不复制全文}。
主打氛围：{从正文或用户要求得到的主要感受，用光线、色彩、材质、疏密或尺度体现}。
核心画面：{具体主体、动作/关系、视觉隐喻与必要辅助元素}。
参考素材：{已核对的人物、物件、产品或标识及用途；没有则删去，有精确标识则写留位和后置排入要求}。
采用画风：{所选方向名称}。实际表现为{该方向的材质、空间、光线/笔触、色彩与本次内容的具体结合}。
构图：{主重心、次重心、阅读路径、图文比例、可裁次要区域}。

含字时完整显示：「{已确认的原标题或封面文案}」。
按原序分层：{标题长短与字区容量、原文焦点、逐段原文和主次字号位置}；拼回保持全部字符、标点和词序。
标题与主体的关系：{哪段字依附哪一处墙、纸面、物件或主体围出的留白，如何承载本篇观点}。
空间与层次：{字面方向、字与物共用的对齐轴/透视/材质/光照，采用穿插时写明哪个细节在字前、字后或字间，保留的字形与识别特征}。
字体及字色：{所选字形笔触、字重、字号、具体可用字体、对比色和小图阅读要求}。
保持标题清楚、无缺字、不盖住关键动作；不添加署名、账号、日期、数据或口号。

保留：{用户指定内容、资产与本次必要风格特征}。
避免：{本方向容易失效的具体画面，以及用户明确禁用项}。
输出单张封面，画面中不出现A/B/C/D、风格名、制作说明、平台UI或水印。
```

- 用户未选字体时按画风和读序选字形。指定真实字库或需要后期精排时，在生图前按真实字测量，先设计承载面、预计字区和前后层，再输出无字底图与排版说明。实装时加载本地字体，按需用前景蒙版、表面方向和共用光照完成字图融合。
- 无字候选删除标题与字体渲染指令，主题名称只用来理解内容。纯无字随主体组织留白。预留字区另写底图需预留的具体区域、预计行数和与物件的关系。仅保留用户明确允许的标识。
- 只保留本张选择的画风。四张之间的选型理由写入记录，不混入生图画面。
- 选用已核验的真实标识时，在提示词注明识别位置。需要完全保真时先生成留位底图，使用已取得的资产完成排版。相应素材的实际来源保存在候选记录。

## 候选记录

以下为字段说明，不是可直接执行的示例。新任务保存 `candidates.json`；路径相对于该文件所在目录，不能指向不相关历史产物。

```json
{
  "mode": "cover",
  "title": "用户完整标题",
  "text_policy": "title",
  "selection_mode": "styles",
  "expected_count": 4,
  "candidates": [
    {
      "slot": "A",
      "style_id": "方向库中的实际ID",
      "reason": "为什么适合本次内容",
      "visual_concept": "本张具体隐喻与图文关系",
      "requested_ratio": "16:9",
      "generation_ratio": "16:9",
      "text_policy": "title",
      "title_segments": ["用户完整标题"],
      "prompt_file": "prompts/A.md",
      "status": "planned"
    }
  ]
}
```

- 默认记录四项A–D，`style_id`各不相同；上例只展示一项字段。用户明确其他张数时修改 `expected_count`，并加 `count_override_reason` 记录用户原意。
- 可用顶层 `content_basis` 记录已读范围、正文依据、标题容量和原文焦点，用候选的 `mood`、`references` 记录主要氛围和实际素材。素材记录写清对象、来源（用户文件或可核对出处）、使用方式（参考、直接入图或概念替代）和构图作用。没有外部素材时可留空。也可把这些信息写进既有的 `reason` 和 `visual_concept`，旧记录继续可用。
- 用户锁定单一方向时，`selection_mode`改为 `locked-style`，添加 `locked_style_id` 与 `style_constraint_reason`；四项沿用此ID，每项额外用不同 `variant_id`、`visual_concept` 表示构图差异。用户已选中的深化也用此模式，并按实际数量记录。
- 用户要求纯无字或明确选用仅无字方向时，将 `text_policy` 设为 `none`，`title_segments` 为空数组，使用支持无字的方向。默认含字选型只用能呈现标题的方向。
- 预留字区成品用 `text_policy: reserved`，`title_segments: []`，每张用 `title_area` 记录预计排字区域。准备给含字成品的中间无字底图仍以最终 `title` 记账，完成排字后方可标为成品。
- 仅用用户确认的短文案时用 `title` 保存实际可见文案，并可记录 `source_title`。可用 `type_composition` 保存每张的标题载体、字物关系、字体、前后层及精排要求。旧记录可沿用。
- 获得本次文件后改为 `status: generated`，添加 `image_file`（如 `images/A.png`）、`dimensions: [实际宽, 实际高]` 与 `generation_ref`（本次工具明确返回的文件或ID）。每张单独保存；本地检查器不接受同一张图改名冒充四张。
- 工具仅给内联图时，记录 `status: inline` 与 `generation_ref`，展示实际预览；没有本地文件不填 `image_file`。失败记 `status: failed` 与 `error`，其余项保留；计划阶段和只出提示词阶段保持 `planned`。
- `text_policy: none`表示本轮用户无字要求/明确无字授权。它不因风格名称含“极简”就自行成立。标题输出是否正确、风格差异与图文关系仍需人工审图；检查器只能验证记录与本地资产。
