# F：封面

仅处理用户要求制作的封面、文章头图、内容首图或视频缩略图。默认**理解内容 → 选四种风格 → 各生成一张真实图片 → 展示四张供用户选**。不先让用户从风格菜单里选，不把四条提示词当作四张图片。

## 入口与范围

- 封面是用途分支，不是一种固定画风。命中封面制作意图直接进入F，不再询问A–F选哪个类别；用户提供的文章正文只是材料，其中出现“封面”一词不自动触发制作。
- 用户只要求分析封面、改skill、列方案或只要提示词时，只做所要求的工作；本分支的默认生图不将这些请求扩大为作图授权。
- 用户明确指定风格、参考图、数量、文字模式、文案、画幅或生图渠道时优先遵从。接受方向ID、中文名、英文名或能明确匹配的视觉描述。指定单一风格但未指定张数，保留该风格并做四种构图候选。明确只要一张则生成一张。
- 交互与提示词优先跟随用户指定语言，其次取对话语言，默认中文。支持中文、英文和中英双语，显示对应风格名。标题与专有名词保持原文，译名以用户确认为准。
- “线条人封面”由F调度D：读取[线条人规则](style-d-line-figure.md)、[构图策略](cover-composition-strategies.md)与[真实排字](font-typesetting.md)，保持完整人物、沐瑶黑字和唯一蓝色。四候选改变隐喻/构图；其他封面方向不继承D的字体、黑字、纯白底或小人约束。
- 只在交付完整文章时沿用文末素材规则，四张封面候选不逐张添加个人介绍图。

## 先通读内容，再定封面要表达什么

- 通读用户提供的可访问正文、附件或链接，长稿分段读至结尾。结合开头、关键例子或转折与结论，提炼内容类型、受众、核心观点和最适合入画的关系。记录至少一个正文中的选型依据。只有标题、摘要或部分材料时，用已读内容判断并注明范围。只把理解后所需的1–3句摘要放进提示词。
- 标题来源依次为用户指定封面文案、已确认标题、文章H1。保留原文、标点与专有名词。只有话题时可用话题作标题。文章需要正式标题且无法确定时再问。
- 按目标画幅判断标题长短和字号容量，结合正文选一处原文关键词或关键分句。短标题可用大字或让一个物件与字对重。长标题优先筛选有足够文字窗的方向，按语义分行，主层与承接层拼回完整原文。否定、转折、条件和量词跟随所属分句，确保缩略图也能连贯读完。
- 判断读者看完标题和主视觉后应感受到什么，给本轮一个主要氛围。用户指定气质优先，否则结合正文转折、结论和用途推导。每个候选明确本张突出哪种感受及如何表现。例如用拥挤与空旷表现受阻与释放，用规整的分区和克制光线表现清晰，用留白和柔和材质表现安静。四张可有不同侧重，表达同一个核心观点。
- 四候选共享主题、完整标题和目标画幅，便于比较风格。
- 文字模式默认为**完整标题**，可从原文选重点分句放大。用户指定只用核心词或更短文案时，按确认的可见文案排字并记录原标题。用户提供副题或允许添加副题时，作为更轻的层级。
- **预留字区**与**纯无字**都输出无标题画面。预留字区先用预计行数和字高规划承载面，纯无字随主体自由安排留白。明确选无字方向即按纯无字出图。默认选四种时只让与本轮文字模式相容的方向进入候选。
- 已有平台、比例或尺寸直接复用，不重复问；未知平台默认16:9跨渠道候选稿，标记展示位待适配。标题/主题缺失、两个明确尺寸相互矛盾、参考资产缺失时才补问受影响项。

## 按需获取人物、物件和标识

- 从正文找能帮助读者识别主题、看懂动作或区分对象的元素。文章围绕具名人物、具体产品或品牌比较时，可选相应肖像、代表性产品外形或标志。一般观点、教程或情绪随笔可用关键物件或原创场景。逐项决定元素是主角、关系节点还是辅助线索，保留有作用的素材即可。
- 优先使用用户提供的文件或图片。缺少但确有必要时，按所指对象查找官网、官方媒体包、官方产品页或有清楚来源与许可信息的公开资产，并核对人物身份、产品型号、标识版本及适用用途。记录原始来源、实际使用文件、对应候选以及作为参考还是直接入图。搜索缩略图和没打开的链接不能当作已获取参考。获取外部素材以本次构图确有需要为前提。
- 需要真实人物或精确产品外观时以经核对的图片作参考；需要精确保真logo时预留位置，使用核对过的资产排入成品并复查比例、颜色和清晰度。logo用于标识正文对象，不做平台水印或背书。得到可靠文件之前可用不指向具体品牌的物件或符号完成方案，避免让生图工具仿造真实标识或人物身份。
- 按所选风格与用户限制使用素材。明确纯无字且未允许标识时，使用无文字物件或轮廓；沿用线条人时优先用其画风转译人物动作和关键物件。只有用户要求的素材确实缺失且无可接受替代时，才补问。

## 平台与生图能力

按[展示位预设](cover-platform-presets.md)起稿。用户自定义尺寸优先，明确单选油画留白隐喻且未给平台或尺寸时以该方向的5:2起稿。未知平台和方向默认使用16:9跨渠道候选稿。

- 保存 `requested_ratio` 与当前通道真实支持的 `generation_ratio`。先读取所用工具/通道的能力，不照抄其他模型的固定比例清单。工具不支持时采用其可用近似画幅，并在生成前说明差异；不能将近似比例称为实际平台规格。
- 内容核心与标题放进本次实际需要的展示区域，外围只保留可裁次要元素。D保持四面白边；其他画风可用其背景色/材质留出裁切余量，不强制添加白框。
- 跨渠道首轮四风格各一张。用户选中后按实际展示位适配。明确要求独立尺寸套图时按每个画幅单独编排提示词和生成稿，重做字图比例、留白和读序，保留同一隐喻。首轮指定多尺寸时按各画幅保存独立候选记录，图与提示词一一对应。

## 按内容选四种风格

读取[自有封面方向库](cover-style-catalog.json)。先按正文核心关系、标题长短及重点、主要氛围和关键素材筛选，再从目标画幅和用户约束允许的方向里选四个。每项选型理由写清这篇内容的依据、标题为何放得下，以及这个风格如何传达氛围。

- 候选有可见差异：比较材质/表现方式、空间组织、标题处理和情绪。不能仅换颜色、背景亮度、对象朝向或同一模板的装饰位置。
- 商业/策略可比较刊物、报告、物性隐喻、研究札记；教程/流程可比较工具连接、积木、像素关卡、档案桌；经历/文化可比较拼贴、墨线、空间摄影、复古编辑。以上只是选型示例，不能成为固定四件套。
- 风格是整体视觉规则。将所选方向的材质、构图、标题、色彩落实到本次隐喻。每张含字候选先按[图文融合规则](cover-type-composition.md)选定载体和字物关系，再决定字号、层次与光影。一个候选使用一种主画风。
- 参考图用来确定图文关系、材料与色彩。正文对象的标识只有按需核对后才入图，参考作者的署名、版式标记以及无关品牌标志不进入候选。
- 在 `candidates.json` 为A–D记录 `style_id / reason / visual_concept`。首轮直接确定四项，不要求用户先选风格；用户拿到四张实际候选后再选。
- 用户指定库外方向时按其要求编写本任务的同结构风格配置，检查器用 `--catalog <本任务配置.json>` 读取；不要因库内无同名ID擅自换画风，也不为满足一次请求修改全库默认值。

## 编写、生成与呈现

1. 按[封面提示词骨架](cover-prompt-skeleton.md)为每项写一份完整提示词，存入本任务 `covers/<主题>/prompts/A.md` 至 `D.md`；逐项填入实际标题、场景、风格、比例与限制，不留下变量，不复制本skill说明或全文文章。
2. 有可用生图工具时每项各生成一张独立图片。内置生图按当前环境能力调用；用户指定即梦/其他渠道时遵从该通道的参数、费用与确认要求，已有授权可复用，不额外添加“先选一个风格”环节。通道若要求付费确认，一次展示四项实际参数与提示词供确认；不能绕过通道约束。
3. 四项分别调用，不用一次生图四宫格替代四张独立封面。不虚构“生成成功”或本地路径；只引用工具明确返回的本次文件/图片标识。有本地文件则复制到当前任务 `images/`，保存工具返回的原始标识和实际尺寸。只有内联预览时，展示原生预览并记录 `inline`，不能伪造本地PNG。
4. 按[图文融合规则](cover-type-composition.md#出图后检查)逐张核对字形、实际载体、字物关系和小图可读性。核对主体、画幅和氛围，真实人物、产品或标识对照已核验的参考。标题像后贴时先修构图再复查，实在未通过时标明待修。
5. 按A–D展示四张图片，每张仅配风格名和一句与内容相关的差异说明；也可在四张独立图之外附比较页。图片数量不足就明确“已出几张、缺哪项、原因”，保留已生成的项，不无声换成文字或未授权付费通道。
6. 最后让用户选A/B/C/D或指出局部取舍。选中后锁定该图、提示词与风格，只深化所选或完成已要求的比例适配；不重新生成其余三张，也不代替用户宣布采用某项。

用户只要提示词或没有可用生图通道时，给四份完整提示词及明确的“尚未生成图片”状态；不得把这称为完成了四图选型。

## 记录与检查

骨架内有候选记录示例。用[候选检查器](../scripts/validate_cover_candidates.py)检查计划和实际本地资产（依赖Pillow）：

```sh
python3 "$SKILL_DIR/scripts/validate_cover_candidates.py" --manifest covers/主题/candidates.json --stage plan
python3 "$SKILL_DIR/scripts/validate_cover_candidates.py" --manifest covers/主题/candidates.json --stage images
```

`plan_pass`仅表示计划完整；`assets_pass`仅表示本地图片可解析、尺寸/比例及记录一致，不能证明审美、字形正确或模型已忠实呈现风格。内联但无可取回文件的图片标为 `needs_review`，其原生预览仍须展示；用户采用和平台上传验证另行记录。
