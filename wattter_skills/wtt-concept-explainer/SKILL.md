# 概念解释器

让读者看懂：有哪些要素、它们怎样关联、改变一个条件会发生什么。视觉形式服务于这个问题；可以直接画关系，也可以借用贴切的实物隐喻。

## 从问题进入

- 从对话确定解释对象、受众、要解决的疑问和交付形式。已有要求直接沿用；未指定时面向初学者，先用一句话确定学习目标。
- 用户只问原理，直接解释；要求图或演示才制作相应产物。要求交互但没指定格式时，能写文件就优先单文件 HTML。
- 动态展示的输出未定时，询问一次：“交互页面（可操作探索），还是视频讲解（旁白带着画面自动演示）？”明确指定页面、视频或两者时直接沿用；纯文字/静态图不问此题。未回复时可先整理共用解释模型，不擅自替用户选格式。
- 选视频后读 [视频讲解制作](references/video-narration.md)，同时读 [视频质量约束](references/video-quality.md)，把主体动作、播放尺度字号和实际审阅写进分镜；先设计旁白、分镜和文字效果，经下述制作前确认后，再实现按时间推进的画面；只要视频时不强制先做完整交互页。用户要带配音的自动讲解网页时，也用该参考编排讲解，交付仍是网页。
- 视频图文与镜头按[产品叙事排布](references/video-layout.md)设计：短主张、大幅主体、留白与逐镜焦点；默认借鉴苹果产品发布/主页的层级。机械/路径类优先从整体连续推近局部、沿连接追踪，保留空间参照，旁白分段不自动切镜；把推进、动作停留与文字避让写进分镜并检查。配色、主体与解释策略继续按内容和用户要求选择。
- 只在缺口会改变解释结论或交付范围时提问；否则说明合理假设后继续。不设固定问卷或方案数；视觉制作统一在设计方案就绪后确认一次，不把每个内部步骤都变成审批。
- 把复杂主题拆成一条主线，相关细节按点击、分层或后续段落展开。不要用“精简”删除用户指定的机制与条件。

## 先确定解释模型

用一段短文或小表说明以下内容；简单任务可融入正文，不必另建计划文件：

- **要素与关系**：对象、方向、条件、阶段或空间位置。区分相关、顺序和因果。
- **规则与依据**：哪些来自用户材料、可核对事实、特定理论，哪些只是教学假设。具体数值与阈值有来源才使用；演示参数明确标为示例。
- **变化与观察**：用户改什么，哪些要素跟着变，读者从哪里看出变化。静态概念可以用前后对照，不强行加入运动。
- **边界**：隐喻覆盖什么、遗漏什么；传统体系中的规则不包装成已经验证的现实因果。

有计算或状态变化时，显示、图形和解释读取同一份状态或规则。不要分别手填数字和动画。多流派或多版本结论确有差异时，标明采用的口径；无法确定时只暂停依赖该口径的判断。

## 先选解释策略，再设计画面

先说明“观众通过什么过程理解”，再决定图形、场景和运动。结构拆解只是一种策略，不能因为现有样例是装置，就把新题材都做成剖面图或关系盘。

| 要讲清的问题 | 优先考虑 |
|---|---|
| 组成、分类、归属 | 分组卡片、层级图 |
| 相互作用、约束、反馈 | 关系图、因果回路 |
| 阶段、时序、前后变化 | 时间轴、状态图、对照 |
| 位置、距离、路径 | 平面图、空间示意 |
| 输入如何变成输出 | 流程、可操作控件、机制隐喻 |
| 置身其中会看到什么 | 情境叙事、空间漫游、第一人称与全景切换 |
| 大小、距离或时间为何难以直觉理解 | 尺度缩放、参照物比较、时间压缩与展开 |
| 换一个条件会怎样 | 对照实验、反事实场景、参数探索 |
| 意象或抽象观念如何理解 | 象征意象、类比故事、逐步映射，注明适用范围 |
| 换一个视角为何有不同解释 | 多视角叠层、并置比较、观察者切换 |

- 根据学习问题选一条主策略，必要时组合。视觉主体可以是场景、事件、空间或连续变化，不限于有零件的实物。玄学不默认套关系盘，宇宙不默认套星空粒子；氛围要帮助定位、感受尺度或理解意象。隐喻不贴切时直接解释。
- 标题说明要回答的问题；短标签和必要图例直接可见。用位置、线型或文字与颜色共同表达差异。
- 每个交互对应一个解释问题，并显示操作后的原因或结果；删除不能帮助理解的装饰运动。
- 按内容选择必要细节，不规定零件数量、画风、画幅、主题数量或制作时长。
- 用户要求视觉图解或演示时，设计阶段先明确主体，确认后再制作承载概念的完整主体；控件与数值只是辅助。不能用两张状态卡、几个按钮或默认方框连线替代主体制作。
- 简化依赖和制作步骤，不降低构图、体积、细节与反馈质量。抽象网络也要设计路径、节点形态、层次与焦点，不因不画机器就退回占位框图。
- 有参考作品时实际查看画面，提取构图、空间层次、材质/线条及运动特征；不要只读说明就声称效果对齐。
- 制作视觉产物时读 [视觉工艺与验收](references/visual-craft.md)，将选定表达落实到可见细节。
- 默认使用克莱因蓝 `#002FA7`、冷白背景 `#F3F6FB` 和深蓝正文；状态辅助色、可读性规则见视觉参考。用户指定配色时覆盖默认；借用旧示例时同步配色，不沿用其历史颜色。
- 机制类图解可按需查看可离线运行的 [缓存装置示例](assets/cache-apparatus.html)：借用投影、表面、状态驱动和回放组织方式，按新概念重做主体。该示例不是所有题材的默认造型；不需要机械风格时不加载。
- 多部件联动可参考 [四冲程发动机](assets/four-stroke-engine.html)：固定杆长约束、相位驱动、剖面与外壳、手动拖动共用一个模型；物理运动的约束不能用独立循环动画替代。它是教学简化，不是 CAD 或真实热力仿真。
- 遇到传统体系、宇宙/尺度题材、隐喻不匹配或需要更具体案例时，按需读 [适配示例](references/adaptation.md)。

## 制作前确认

适用于静态图解、交互页面、视频和自动讲解网页；纯文字问答直接回答。流程为“解释模型 → 解释策略、构图、脚本与图例预览 → 用户确认 → 正式制作”。

- 先交一份可审阅方案：**解释策略**（用什么体验/推演讲清楚，为什么适合）、**内容**（学习目标、解释顺序、确切文案/脚本）、**构图**（主体、布局、阅读顺序、标签位置）、**图例**（具体对象/隐喻及其含义、配色与风格）。视频包含完整旁白、分镜、文字效果和估时；交互页说明每次操作前后的变化；静态图给标题、标注和阅读路径。
- 图例方向优先用低成本图片呈现，做法见 [视觉参考](references/visual-craft.md)。展示的是待确认的构图/主体样图，不只是色板，也不把装饰参考当作机制正确的证明；复杂方案按关键差异补必要样图，不固定数量。
- 把方案版本与预览一起展示，明确请用户确认“解释方式、内容/脚本、构图、图例方向是否按此制作”。未得到明确回复就停在待确认；可以继续资料核对和草案修订，不做完整交互页、精细主体建模、批量素材、正式配音、动画实现或整片渲染。少量用于确认的静态草图/截图不受此限制。
- 用户只选颜色、只认可图例、只指定输出形式，均不等于确认其余内容；只问尚未确认的部分。“你来设计”不自动免除这一步。用户明确要求免确认直接制作时，记录其指令并遵从。
- 已明确确认的同一版方案沿用，不重复询问；文件可写时在现有方案/分镜中记录版本、待确认或已确认、用户确认范围和依据，不另建审批系统。助手自行拟定的计划、自动检查通过和超时均不能记为用户确认。
- 确认后改变解释策略、核心解释、图例隐喻、主体或主要构图，先展示受影响部分的修订再确认；排版修复、纠错和不改变内容的配音校时直接执行。用户已明确指定的具体修改视为该范围授权，未受影响部分继续沿用。

## 按现有能力实现

能力指当前实际可调用的工具，不由模型品牌推定。沿用用户指定工具和项目约定，不为本 Skill 安装整套框架。

| 当前需求与能力 | 做法 |
|---|---|
| 只需文字，或只有对话能力 | 用文字、表格、字符图；用户要代码时可交付完整源码文本，并说明尚未保存或运行 |
| 关系或流程图 | 可用 Mermaid；不能确认宿主支持时，同时保留可读的文字关系 |
| 独立静态矢量图 | 用 SVG，保留可编辑文字；不引入 JS 或构建系统 |
| 独立交互演示，可写文件 | 默认原生 HTML/CSS/JS，内联必要样式和逻辑，优先离线打开 |
| 视频讲解，有声音、渲染与编码能力 | 同一解释模型加导演时间轴，按分镜自动演示、突出关键词和局部，再导出带旁白 MP4；沿用现有工具，详见视频参考 |
| 已有前端或文档工程 | 沿用已有组件、图表或渲染方式，不另起框架 |
| 用户需要插画且有图像工具 | 生成视觉素材；精确数字、关系与正文仍由可核对的文本/代码承载 |
| 真实 3D 或复杂场效果不可替代 | 才考虑 3D/WebGL；说明新增依赖与无特效时能保留的解释 |

没有专用工具时不要虚构调用。缺少浏览器不阻止写 HTML，但渲染和交互状态记为未验证。用户指定的格式无法生成时，交付可行部分并说明缺口，不把提示词叫作图片、源码叫作已运行页面。

## 验证解释与产物

- **语义**：学习问题是否得到回答；连线方向、条件和术语是否一致；隐喻有没有偷偷增加规则。
- **变化**：有模型时检查一个正常输入和相关边界，例如阈值相等、空集合、首尾阶段、重复操作；验证显示与实际状态一致。
- **画面**：有渲染工具就查看整体和关键局部；网页检查窄屏，视频检查目标画幅与字幕安全区。核对主体辨识、空间关系、工艺细节和阅读顺序。有参考时同尺度对照，记录差距。没有渲染能力明确标为视觉未验收。
- **交互**：有浏览器时实际操作关键路径；原生按钮/输入优先，支持键盘；持续动画才处理暂停和减少动态效果。
- **视频**：按[质量约束](references/video-quality.md)检查实际播放尺寸、主体动作、逐句焦点与转场；正式渲染前和最终MP4后分别看画面与连续片段。技术检查不替代视觉检查；保留绑定当前成片指纹的审阅记录，待审/失败不称通过。旁白对应时刻、乱序重绘、声音和完整解码继续核验。
- 纯文本任务不运行浏览器；平面关系图不做几何碰撞审计。检查范围随实际产物决定。
- 功能通过不能替代视觉通过；检查运动过程中主体如何变化，不只检查按钮与读数。

## 交付

- 只交用户需要的形式，不固定输出五件套。文件写入当前项目或指定目录，给出实际链接。
- 短述怎样读、怎样操作、采用的规则，以及做过与没做过的验证。区分结构检查、实际运行和用户采用。
- 视频交付带声音 MP4、可改源码与分镜/时间轴、实际验收记录；若用户仅要剧本或分镜，止于所选范围。没有配音或导出能力时明确缺项，不能把 HTML、静音预览或分镜称为讲解成片。
- 视频能力由本技能的 scripts、模板和制作契约独立提供，不调用或要求安装其他 Skill；入口见 [视频工具](references/video-production.md)。Python、Node、FFmpeg、Playwright、TTS 后端/模型和用户音色数据使用现有外部安装，缺项时报告具体工具与可交付范围。
