# 视频讲解：让旁白带着模型演示

用于视频讲解或带声音的自动讲解网页。沿用已确认的要素、规则、主体和视觉方向；不能只给普通循环动画铺一段旁白。每次同时执行[视频质量约束](video-quality.md)，统一主体动作、播放尺度字号与两次视觉检查。

## 先确定成品

- 用户已选择视频就进入脚本与分镜设计，经主指令的制作前确认后才正式制作；只要分镜/剧本时只完成该部分。不再询问页面还是视频。
- 未给画幅时用 16:9、1920×1080、30 fps；用户指定其他画幅时重排主体、标签与字幕，不裁掉关键关系。时长由内容、动作和实际旁白决定，不套用固定片长。
- 已有页面或用户要求沿用外观时保持主体、配色和投影，按视频阅读距离调整构图。全新视觉方向先给有依据的候选让用户选；明确委托代选则先选出方向纳入确认方案；既定外观无需重选，但不替代脚本与构图确认。
- 确认后，只要视频可直接做固定画幅舞台；两种输出共用模型和绘制层，分别由用户操作与导演时间轴驱动。自动讲解网页用音频播放位置驱动画面；暂停/跳转时同步重算，切到手动探索时暂停讲解，返回讲解恢复对应时刻。

## 旁白与分镜先于动画

图文构图按[产品叙事排布](video-layout.md)落实：一镜一个短主张，以大幅主体和留白建立层级；完整机制沿镜头展开，不把全部步骤压进常驻侧栏。

先选解释策略：可以是结构与机制，也可以是空间旅程、尺度缩放、意象故事、对照实验或多视角观察。讲述和镜头都围绕它组织；不强制“逐个介绍部件”。先写一条学习主线，例如“为什么活塞往复能让轴旋转”，再写每段旁白及其可见证据。一个镜头承担一个主要新信息；先定位整体，再看局部，最后回到整体验证。

在产物目录保存可编辑的 `storyboard.md`。每镜使用稳定 ID，至少填写：

| 字段 | 要写出的具体决定 |
|---|---|
| 学习目的、旁白 | 观众这一镜要理解什么；可直接配音的完整句子 |
| 景别与构图 | 全景/局部、焦点、主体位置、相机起止位置、字幕与标签避让区 |
| 镜头接力 | 按[机械/路径镜头规则](video-layout.md#机械空间与路径类镜头)写当前目标、保留的空间参照、从上个焦点如何推近/跟随、何时稳住看动作、观察停留及如何接向下一处；不适用时说明采用的切镜关系 |
| 模型/场景起止状态 | 角度、开关、节点、位置、观察者、尺度或时间状态；是否停住、慢放、重复；沿用采用的规则，区分实测、模型和象征场景 |
| 动作与语义触发 | 哪一句/哪几个词对应运动、指示线、局部放大或高亮；起止和保持时机 |
| 文字与效果 | 屏幕确切文案、层级、输出字号和最小播放宽度、位置、进入/强调/退出方式；不要只写“加文字特效” |
| 转场与声音 | 接续哪个状态、是否切回整体；旁白、必要音效或留白 |
| 估时与实际帧 | 动作/阅读最低时长、配音前后停顿；配音后回填帧区间与事件帧 |

可用“问题 → 定位要素 → 分步机制 → 完整演示 → 回扣问题”，也可用“进入情境 → 改变视角/尺度/条件 → 观察差异 → 解释 → 回扣问题”，按内容选择，不必混用。不要把文章每段变成一屏字幕；每段旁白都应找到画面上的解释证据。出现教学假设时在相关镜头注明，不只藏在片尾。

## 设计完成后先确认，再配音和实现

- 将当前版本的完整旁白、分镜、估时与关键构图/图例样图一起交用户审阅，具体预览方式见 [视觉参考](visual-craft.md)。确认请求明确覆盖解释策略、内容、构图、图例及文字效果；尚未真实配音的时间标为估计。
- 在 storyboard.md 记录方案版本、确认状态及用户明确批准的范围；既有方案已全部确认则复用记录。仅同意外观、配色或视频形式时，保持脚本等未确认部分待确认，不擅自合成声音或编写完整动画。
- 未确认只修订方案与必要静态样图。确认后才接入 TTS、制作精细主体与动画、锁时和导出；真实声音造成的小幅校时不重新审批，改台词含义、删减内容或换图例时回到受影响部分的确认。
- 此步骤确认制作方向；下游素材校验与最终验收仍按各自规则执行，不能互相替代，也不对已确认的同一方案重复询问。

## 文字效果承担解释任务

- 分开三层：短标题说明阶段，关键词/标注指向当前对象，字幕承载旁白。不要在三处同时重复整句话。
- 标题切换与阶段切换一致；关键词在说到前可短暂引入，说到时强调，随后保留足够阅读时间。字幕按短句分段，避开运动路径、标签和局部放大区；以最终画幅检查字号与换行。
- 因果关系用箭头描画、路径行进、词组依次出现；对照用并列和局部变色；数值变化读取模型。淡入、下划线、轻微位移通常够用，不给所有文字逐字跳动。
- 打字效果只用于逐步推导或确有阅读目的的文本；字幕不等待长动画才能读完整。术语首次出现可加短释义，不能靠旁白没讲的装饰文案补关键结论。
- 高亮、移动镜头和文字进入避免同时争抢注意力。先让观众找到部件，再演示运动；复杂瞬间可停住或慢放，但不能改变机制关系。

## 同一个模型，两个驱动入口

保留现有计算和绘图。交互驱动提供参数；视频驱动从绝对帧号得到模型参数及镜头、文字、高亮状态，调用同一模型和绘图逻辑。外观不变不意味着原页面可直接导出：先补可重复的帧入口。

示意组织（不是要求安装的新框架）：

```js
async function renderFrame(frame) {
  const cue = sampleTimeline(frame); // 每次返回完整状态，含镜头/文字/高亮
  drawModel(computeModel(cue.parameters));
  drawCameraAndText(cue);
}
```

- 每帧完整重设画面；跳到任意帧后再回同一帧，输出一致。固定随机种子，气流粒子按绝对时间计算，不依赖上次位置。
- 导出不使用真实时钟、累计 deltaTime、未暂停的 CSS 动画或自动点击按钮驱动；暂停镜头中模型保持不动，文字和相机仍可由各自明确的事件变化。
- 发动机放慢的是曲轴相位推进；活塞、连杆和气门仍从同一相位计算。不得单独给活塞减速而曲轴照常旋转。
- 转场复用同一主体并交代观察位置。导出隐藏播放按钮、滑杆及调试读数，保留对解释必要的标签；交互版继续保留操作能力。
- 相机/视窗执行分镜中的接力轨迹，读取整段绝对帧号；跨语音段保留同一主体位置、比例与观察方向。实现与避让细节见[机械/路径镜头规则](video-layout.md#机械空间与路径类镜头)，不要仅因下一段配音开始就切换到独立部件图。

## 配音后锁定时间

- 先按台词和动作估时；生成或接入真实音频后测量时长。镜头时长取“动作/阅读最低时长”与“开口前停顿 + 实际旁白 + 句尾停顿”中的较大值，换算成整数帧。
- 将“阀门关闭”“点火”等关键语义触发定位到实际音频；用已核对的转录/对齐结果或试听标记，回填事件帧。只按字符比例分配的字幕是近似值，不能称逐字同步。
- 锁定后的时间轴是执行时序唯一来源；分镜实际时间从它回填。旁白改变后重校受影响镜头和后续起点，复核字幕、动作及转场，不保持旧事件时间硬套新语音。
- 配音优先用户本次要求或有效默认音色；若指定音色缺失/损坏，报告缺项并继续不依赖配音的工作，不静默换声音。外部音频须核对台词。音乐按需添加，不能遮盖人声。
- 硬时长不够时明确超出多少、删改哪些内容可满足；不自动加速旁白或切断句尾。无时长限制按内容完成。

## 本技能独立制作

- 设计确认后使用本技能 [制作契约](video-production.md) 的初始化、配音、素材锁、锁时、混音、预览、渲染和合成命令，无需读取或安装其他 Skill。
- 浏览器舞台使用 `#stage`、`window.renderFrame(frame)`、`window.__filmMeta`、`window.__ready`；DOM/SVG/Canvas 都可适配。自带轻量模板只验证帧接口，按已确认方案重做主体，不把模板默认外观当作成品设计。
- 保留兼容的 `code-animation/v1` 数据字段；它是本地协议名，不是外部 Skill 调用。`visual` 和自定义导演字段由场景代码实现，不自动生成图形。字幕默认按字符权重近似分配，关键语义事件另行校时。
- 配音使用本技能 [声音入口](voice.md)，优先既有默认音色；也可接入其他 TTS 生成的已核对音频。第三方程序/库、模型和用户音色数据共用外部安装，不复制进 Skill。
- 所有入片媒体按本技能 [素材审阅](material-review.md) 记录来源、版本与使用依据。已有锁的媒体变动走候选；代码排版修复无需重新确认。源码不打包私人配置、录音、凭据或模型权重。

## 成片验收与交付

- 按[两次视觉检查](video-quality.md#两次视觉检查)完成渲染前与最终MP4后的核对；不能以单帧、背景慢推或文字淡入替代主体动作检查。至少复查同一帧在乱序调用后是否一致。
- 看连续片段并试听，验证“讲到哪里，画面就演到哪里”；静态截图与时长相等均不能证明音画同步。不能试听时如实记录，不把自动检测写成人工验收。
- 检查实际尺寸、帧率、总帧数、音画时长、音轨存在、无截句/尾部黑帧、完整解码。具备编码能力时交付常见可播放的 MP4（如 H.264/AAC），同时保留可修改工程、分镜/时间轴和检查记录。
- 自动讲解网页核对播放、暂停、拖动与恢复时的声音/画面一致性；MP4 本身不提供点击交互，不承诺保留网页操作。
- 当前输出不足以成为所需成片时，明确标“分镜草案 / 静音预览 / 待配音 / 待导出”。不把可行性设计、脚本通过或单张截图写成真实视频生成通过。
