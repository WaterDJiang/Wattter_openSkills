# 视觉工艺与验收

用于图解、SVG、交互与视频画面；纯文字回答不加载。轻量指依赖少、结构清楚，视觉质量仍以实际产物为准。视频另读 [视频讲解制作](video-narration.md) 编排镜头和文字，并按[视频质量约束](video-quality.md)执行字号换算、主体动作与最终成片审阅。

## 画面先有主体

先用一句话写“观众看到什么、哪里发生变化、变化解释什么”，再落实图形。一个存储匣搭配到期表盘可以解释固定 TTL；关系盘可以解释多节点的方向；房间模型可以解释空间冲突。

主体可以是一个空间、一场事件、一段变化或一组观察对象，不必是可拆开的装置。主体占据画面的视觉重心，标题、图例和控件围绕它服务。把控制区遮住后，仍应能辨认主体和至少一条核心关系。用户只要数据面板或文字时无需强加插图。

## 确认用图例预览

这里的图例包含用来解释概念的主体、示意对象或隐喻，不仅是颜色图例。按主指令的制作前确认流程，先用必要的代表画面让用户判断“用什么讲、放在哪里、怎样看懂”。

- 优先复用已有截图或用户参考，注明拟保留与拟改变之处；缺少合适参考时，可做轻量 SVG/静态 HTML 草图并渲染为图，或用可用图像工具生成方向样图。不要为了预览先完成整套装置或交互。
- 样图标注“构图/图例方向预览”，显示主体轮廓、关键要素及关系、标题/标签/字幕区域和配色；配短说明解释采用何种解释策略、对象对应哪个概念、变化发生在哪里。精确关系和文字须人工核对，生成图的细节不直接当作事实。
- 使用目标画幅；代表图能说明方向时不批量生成。出现不同主体、关键状态或明显不同构图时，再补必要对照；视频可用关键帧缩略图配分镜，不先渲染整段动画。
- 将实际图片展示或链接给用户，再请求确认。没有图片/渲染能力时明确说明，交文字布局或可读字符草图让用户确认，不把代码或提示词叫作图片，也不擅自跳过确认。
- 图片认可仅覆盖所示范围；完整脚本和构图仍按主指令确认。确认记录随方案保留，正式制作以已确认版本为依据。

## 默认配色：冷白、克莱因蓝与蓝钢

图解、交互页面和视频共用以下默认色；用户明确指定其他风格或已有项目配色时沿用其要求。颜色写入样式变量或集中配置，避免与具体渲染工具绑定。

| 用途 | 颜色 |
|---|---|
| 背景 | 冷白 `#F3F6FB` |
| 主色、标题、主要按钮、关键结构 | 克莱因蓝 `#002FA7` |
| 正文 / 次要文字 | `#142746` / `#4B627F` |
| 分隔线、边界 | `#9CB2CF`，不用于正文 |
| 辅助强调 | 青绿 `#08798D`、深金 `#86630D`、暖橙 `#A84B23`、蓝灰 `#53677D` |
| 柔和暖色填充 | `#DC9C57`，不用于小字 |

主色控制标题和视觉锚点，主体用浅蓝灰明暗表现厚度，保留大面积冷白。辅助色只区分解释中的阶段、方向或焦点，不要求每页全部出现；发动机示例分别映射进气、压缩、做功、排气，其他主题重新定义语义并加文字或线型。

正文及状态标签对实际底色至少达到 4.5:1；浅填充、气体与装饰线不能直接复用为正文色。按钮、选中状态与视频字幕分别检查实际背景，不能只测背景色板。交互页与视频使用同一套颜色角色。

## 不同形式，共同工艺

视频采用[产品叙事排布](video-layout.md)：大幅主体、短主张与留白，按当前语义呈现标签。此布局优先于旧示例的页眉/侧栏组织；旧示例可复用模型和投影，不直接照搬完整页面。

| 形式 | 做到哪些可见细节 |
|---|---|
| 机制装置 | 一致投影、真实厚度、顶面与侧面分明、部件接合、支撑和路径端点；刻度、边缘、槽口来自部件用途 |
| 关系网络 | 节点有语义层级、连线方向清楚、交叉可区分、标签安放合理；局部选择后仍能定位整体 |
| 时间轴 | 当前状态、历史和未发生部分明确；转折与条件能看见，不能只有数字刷新 |
| 空间场景 | 物体有占用范围、路径有起终点、遮挡与前后关系清楚；尺寸未知就标示意 |
| 空间漫游与尺度旅程 | 保留定位参照，标清尺度/时间的变化；镜头移动不混淆对象运动，非等比和压缩段有提示 |
| 象征意象与情境故事 | 意象与概念有明确对应，场景变化承接解释；氛围不能替代关键关系和依据 |
| 对照与观察者切换 | 保留可比较的条件，突出实际变化项；明确不同视角属于同一对象还是不同模型 |

不靠阴影、渐变和边框数量堆精致。材质和微细节应依附真实形状；线条连接到对象，标签不漂在歧义位置。色彩优先强调当前解释对象，其余结构保留可读对比。

## 让交互发生在主体上

- 控件改变状态后，主体中的路径、位置、开合、刻度或层级随之变化。
- 使用同一状态计算图形、读数和解释；若展示过去一次事件的动画，明确是路径回放，不伪装为当前处理状态。
- 动作应有连续起止，速度以能读懂为准；重复点击要能重播或清楚禁用，不能让两条矛盾路径同时运行。
- 长循环、自动演示提供停止；减少动态效果时保留静态终态与解释。
- 不要求物理引擎。CSS 过渡、SVG 路径与少量原生 JS 足以完成许多细腻反馈。

## 依照参考检查

有参考先看真实图或页面，再描述要保留的品质；不用作者的代码行数、工时估计或零件数量作质量替身。

- **整体**：主体是否明确，视觉重心与留白是否成立，阅读顺序是否自然。
- **局部**：查看关键接合、路径端点、表盘刻度、标签；有无穿插、断裂、错位或文字重叠。
- **状态**：初始、操作中、操作后三个状态是否都读得懂；是否只改了辅助面板。
- **目标画幅**：网页核对窄屏主体、标签与控件；视频核对实际输出画幅、字幕安全区和局部放大后的线条/文字；必要时重排说明，不能仅整体缩小。

交付所选形式的实际产物及必要画面证据，说明实际看过哪些状态；视频还要检查连续动作与声音。参考更精细时如实指出差距；用户未采用时不把自主评审写成用户认可。
