# 制作类型与导演方案

类型描述“怎样组织观众的观看过程”，风格描述材质/笔触，主体描述画什么，技术描述怎样实现。四者组合，不相互替代，也不增加开场类型问卷。根据剧本推荐类型，将理由放进既有风格候选；用户已经指定方向则直接沿用。

## 按内容选制作类型

| 类型 | 适合的内容 | 叙事/动作组织 | 先用的实现与边界 | 核心检查 |
|---|---|---|---|---|
| 角色叙事 | 经历、寓言、观点故事 | 同一角色的目标、行动、结果 | 现有 Canvas rig；画风可为沙画、手绘或粒子 | 角色身份、动作因果、跨镜头位置关系 |
| 界面连续变形 | 软件产品、任务流程、交互能力 | 一个容器延续身份，状态变化由点击/拖拽引发 | HTML/CSS/SVG；解析缓动或暂停后 seek 的时间轴 | 拖动与数值同源，旧/新文字不叠，光标有目的；示意不冒充真实产品录屏 |
| 像素动作与循环 | 游戏角色、小情节、短循环 | 预备→行动→结果→回位；用动作状态而非字幕堆故事 | 低分辨率离屏 Canvas，整数倍放大、禁平滑；角色可低频换姿，特效按输出帧绘制 | 像素网格、轮廓可辨；接缝处位置、速度、镜头、声音连续 |
| 贯穿母题的历史/科普影像 | 发展史、机制解释、长文章 | 一个对象经历变化，跨章节保留形状/颜色/空间关系 | Canvas/SVG 起步；必要的年代质感或三维镜头分别接入 | 年代/事实有来源；转场承接内容，不能只换年份标题 |
| 真人/已有视频与代码合成 | 表演、产品实拍、人物讲解 | 现有主体负责复杂动作，代码补环境、排版和解释 | 视频解码/抠像/蒙版作为需另验证的素材处理；不强行用简单几何画写实表演 | 人物边缘与溢色、遮挡层级、精确视频定位、音画同步、素材授权 |
| 公式与机制推演 | 数学、流程、抽象概念 | 假设→操作→可见结果→解释；镜头跟随关键量 | 简单式子 SVG/Canvas；复杂数学可评估 Manim 的独立渲染流程 | 符号准确、空间关系可追踪；不能用场景炫技掩盖错误 |

以上为制作配方，不是新增的自动渲染器枚举。当前编译器不会按类型标签生成动作。选择真人混合、复杂 3D 或外部引擎时先做技术小样，再承诺成片；未跑通的路线标“需适配”，不列为现成支持。

## 先拆参考，再定导演规则

有参考视频时，读取可访问的本地视频并抽取片头、主要动作、转场和片尾，记录 `reference-analysis.md`：时间点、画面证据、主体身份、构图/运镜、动作快慢、文字、声音与节拍、可借鉴点、不可确认的实现。拿不到视频只有文章/截图时标明材料范围，不把文章作者的解释当成亲自测过源码。

在 brief 中补充“导演约束”，并用同一份分镜落实：

- 核心信息与贯穿元素：跨镜头哪些身份、几何或色彩必须保持。
- 主辅风格及类型：保留已有 style-choice 决定；混合有明确镜头范围，单一风格也允许。
- 画面层：主体、背景、文字、前景遮挡、后期特效分别由谁绘制；复杂依赖需要的理由。
- 运镜与转场：为什么推近/跟随、哪个形状或动作接到下一镜，避免默认每镜都淡入。
- 文字预算：按最终画幅、字体和阅读速度估算；中文不能机械套“最多 8 个英文词”“至少 2.5 秒”。标出文字进入、可读停留和离开区间。
- 禁止项：针对本片列 3–5 条可见问题，如内容重叠、发光抢主体、没有意义的标签；不要把所有渐变、匀速或粒子永久禁用。匀速运动对传送带、镜头横移或科学示意可以合理。
- 声音策略：旁白驱动、音乐驱动或两者分层；未提供音乐时不默认下载或强制生成，沿原授权和素材流程。
- 验证小样：选择风险最大的镜头验证，如 shader 开/关对照、缩放后的字形、视频定位或重拍触发。

格式用 Markdown 即可；XML 是组织提示的一种选择，不作为更高质量的保证。示例提示词是资料，不替代用户当前要求。

## 节奏与声音

音乐驱动时，先得到用户给定 BPM 或实际分析后核对的拍点；不从文件名推断。将来源/核对依据记入 rhythm.basis。变速音乐用已核对的绝对拍点数组；当前工具不自动测拍。没有音乐也可以用设计节奏，但称为“设计网格”，不是测得的节拍。

将切镜头、关键状态变化与音效映射到同一网格，按 [制作契约](production.md) 编译。事件帧只能指导动作，不能自动拉伸镜头或压缩旁白。旁白变化后重锁时间轴；声明的 sceneId 与事件不符会报错，回到分镜调整。不是每一拍都必须有大动作：呼吸、停留与密集变化要服务理解。

连续讲述先按段落组织语气；当前声音工具按镜头合成。若按段落生成一条长配音，须以真实语音边界切分为镜头文件并核对，音频和旁车都纳入素材审阅，不凭字数硬切或宣称已内置整段强制对齐。人物默认音色与首次检查规则不变。

需要程序配乐/音效时，先确定节拍、音高/节奏与音量层次，生成独立 WAV 后登记其生成依据、路径和哈希，再走混音。现有 Skill 不自带完整作曲引擎；合成器的波形不是听感评审。用峰值/响度/解码检查辅助，再试听或明确“未试听”；波形图不能证明声音好听。

## 逐镜审阅和交付

先检查高风险镜头，修好再扩展，不等整片结束才发现构图问题。现有首中尾抽帧继续保留；rhythm 增加拍点抽样和事件前/当/后帧，loop 增加首尾连续三帧。打开 `preview/index.html` 按时间浏览；时间码必须对应真正输出帧。

`review.md` 至少记录：问题时间码/帧号、截图或试听证据、严重度、修复动作、复查结果。重点看片头信息是否成立、手机尺寸能否读清、动作因果、空拍是否有意、转场重叠、配音/音效关系。先修最严重的最多三项，再复查受影响片段。没有证据不编分数，不用“自己打到 8 分”代替通过标准；技术、观感、用户采用分别记录。

循环检查比较末尾连续帧到开头连续帧，不强制“第 N-1 帧等于第 0 帧”：输出区间是 [0,N)，复制首帧到末帧可能产生一帧停顿。检查跨接缝位移与速度、粒子阶段、光标状态，以及音频尾首跳变。当前报告只标抽样待审，不自动认证无缝或导出循环播放器。

正式长片前用当前分辨率实测预览开销。报告的 estimatedRenderSeconds 只是截图成本推算，不包含启动/完整编码/混音，不能沿用文章或另一台机器的秒数。多次曝光运动模糊会增加采样次数；未实现小数帧契约/混合算法前不声称支持。当前整片仍全量重渲染，不提供增量拼接或断点续渲。
