# 剧本之后，由用户选择风格

## 时机与边界

视频制作顺序：**理解内容 → 生成/改编剧本 → 推荐候选 → 用户选定 → 完整分镜与视觉实现 → 原制作管线**。

风格选择是本 Skill 的明确交互节点。用户已经选过的风格继续有效，不重复索要批准。一般的“直接跑完”“别逐站确认”只免除后续逐站确认，不能替代尚未作出的风格选择；若用户针对本片明确说“风格你来定”，则记录该委托并选择，不再反问。

只写剧本、技术分析、已有视频的无关小修时，不额外设置本节点。原文明确指定的画风，或当前对话已经明确选定的画风，作为已有选择；单纯提供参考视频不自动等于要求照搬其中所有风格。

## 先形成可供判断的内容

- 新工程先按制作契约 init 空目录，再保存这些文档；初始化只复制基础文件，不代表已选择模板画风。
- 先保存 `script.md`：核心信息、故事或论述主线、可见动作、旁白草稿、估计时长。现成剧本做必要视觉化，保留原意；文章/主题先编成适合动画的内容。
- 此时可写粗分镜和依赖调查，不提前定死画风、生成整片视觉资产、写完整场景或导出成片。
- 阅读 [风格目录](style-catalog.md)，用剧本中具体镜头解释选择；不只说“高级”“震撼”“适合传播”。

## 提供 1 个推荐 + 2 个备选

输出保存到 `style-options.md`，使用短表：

| 选项 | 风格方向 | 对本剧本为什么合适 | 同一个关键镜头会怎样呈现 | 必要限制 |
|---|---|---|---|---|
| A（推荐） | 主风格；需要时附一种辅助形式 | 对应具体情节/信息表达 | 写角色/对象、动作、材质 | 仅写影响选择的限制 |
| B | 与 A 有明显视觉差别 | 同一内容的另一种表达理由 | 使用与 A 相同的镜头比较 | 同上 |
| C | 第三种可执行方向 | 说明取舍 | 仍比较同一镜头 | 同上 |

- 推荐项放第一位，但不预先采用；不要将“A 推荐”写成“已选 A”。三个选项都必须可承接用户内容，不用明显差的选项凑数。
- 只展示与当前剧本相关的三种，另说明可自定义、要求更多风格或选择有目的的混合。用户要求看全部时展示目录摘要。
- MG 是表现形式，混合画风是编排方案；不要拿库名与艺术风格并列让用户选。
- 没有三种合理可行方向时，说明约束，给实际可行选项，不承诺不具备的工具。对需新实现的风格标“按本片实现并验证”；涉及 2D 黏土近似/真实 3D 等效果差别时写清。
- 用户选择混合时，给明确主风格、辅助风格和使用镜头；若用户已经明确了组合，直接记录。只有影响全片的组合关系仍不清楚时再问一次具体问题。

## 收集选择与等待

优先用当前环境可用的交互提问工具发一个问题，选项文字为 A/B/C 的实际风格名，推荐项排第一。问题注明可自由输入自定义方向；工具自带自由输入时不要另造“其他”占位选项。没有工具时用一条简短问题列出 A/B/C。

示例（须替换为本片内容，不照搬）：

> 剧本是“小女孩把破碎风筝修好，让它重新飞起来”，约 50–70 秒。推荐 A 手绘纸纹：手、纸和修补动作容易看清。B 沙画：碎片聚成完整风筝；C 复古网点：用少量叠色表现风和飞行。你选择哪种？也可以指定其他风格或组合。

没有明确回复时保持待选：

- 保存剧本与候选，`style-choice.md` 写 `status: pending`。
- 不把超时、预选按钮、沉默或历史其他片子的偏好当作本片确认。
- 可继续查素材/依赖等不依赖风格的准备；不能进入依赖选择的视觉制作。若需要结束当前轮，明确“剧本和候选已保存，等待风格选择”，不要报告整片已完成。

## 记录与落实

`style-choice.md` 是本片风格决定的唯一记录；不要给 brief、分镜和工程各写一套冲突的审批状态。

```text
status: pending | selected | delegated
script: script.md
options: style-options.md
selected_direction: 未选择时留空；选择后填写实际方向
primary_style: 风格目录 ID 或自定义描述
supporting_styles: 可为空；写使用范围
presentation: MG / 跨风格叙事 / 无等
user_basis: 用户本片选择的原话及会话位置；不是模型推测
implementation_scope: 例如“前端 2D 黏土近似”；未知时写待查
```

- 用户选 B 就执行 B；不得以 A 更合适为由改回推荐项。用户已经明确风格则直接写 selected 和依据；明确委托代选则写 delegated、授权原话和实际所选方向。
- `brief.md` 和 `storyboard.md` 引用该记录，把决定落实为色板、笔触/材质、主体设计、动作与逐镜风格。`film.json` 与 `scenes.js` 按完整分镜实现；目录 ID 不会自动激活渲染器。
- 用户改选时保留原决定与变更说明，更新同一记录，标出需重做的分镜、资产和画面；台词/旁白未改就不无故重写。
- 实现中需实质改换风格或将真实 3D 降为 2D 时，说明具体障碍和可选替代，等待该项决定。局部修正颜色、避开遮挡、优化速度且不改变已选风格时直接执行。
- 风格确定后继续完成已授权的成片制作，不再机械要求剧本、分镜、配音、导出逐站批准。
