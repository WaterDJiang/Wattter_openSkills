# 前端画法与选型

## 渲染层和时间轴层分开

Canvas、p5.js、SVG、PixiJS、Three.js 负责画面；统一时间轴负责哪一帧处于什么状态；浏览器负责把画面栅格化；FFmpeg 负责编码与混音。Remotion 可以替换编排/渲染层，但不是沙画或粒子的画法本身。

附带脚本真实支持的是浏览器 `#stage` 区域截图与 `renderFrame(frame)` 契约。默认模板为 Canvas 2D。以下是选型与适配方法，不代表已为所有库实现现成适配器。

完整风格配方见 [风格目录](style-catalog.md)；风格是否采用按 [用户选择流程](style-selection.md)。本页只指导已选方向的技术实现，不能绕过用户决定。

## 按内容组合，不做互斥分类

| 维度 | 问题 | 示例 |
|---|---|---|
| 主体 | 观众看到什么，是否是同一个对象？ | 角色、地貌、文字、图表；稳定身份 ID |
| 视觉风格 | 对象呈现什么材质和笔触？ | 扁平、手绘、沙画、水墨、粒子构成 |
| 动作与效果 | 对象怎样行动或出现？ | 行走、转身、轻摆、描边显影、粒子聚散 |
| 实现技术 | 哪种实现最少够用？ | Canvas、p5.js、SVG、DOM、WebGL |

粒子是绘制元素，也能用于聚散效果；“粒子角色”和“角色化为粒子”分别描述外观与变化。沙画角色、沙画风景和沙画文字共用风格，但主体几何不同。不能把主体/风格/效果混成一个必选类别。

从每镜的叙事目的出发记录推荐理由；用户选定后在该方向内实现。风格不必逐镜变化；沙画不天然等于回忆，粒子不天然等于科技。用户指定风格时优先遵从，在该风格内寻找能讲清内容的动作。动作、轮廓和表情要在加纹理前可读。

同一主体复用局部几何/rig、比例、配色与身份；从该几何生成遮罩或目标点，再套材质、动作和效果。点集与随机源按身份固定。转场保持轮廓、位置、动作阶段或明确设计衔接，不能换风格就换脸。

| 实现需求 | 先选 | 增加依赖的条件 |
|---|---|---|
| 角色/风景/文字的路径与轮廓 | Canvas 2D；曲线/噪声便利可用 p5.js | 大量精灵或贴图批处理才考虑 PixiJS |
| 任意主体的沙画/涂抹外观 | 离屏主体层 + 遮罩 + 固定沙粒 | 大分辨率/粒子量先实测，再考虑 shader |
| 任意主体的粒子构成与聚散 | 主体采样点集 + 固定映射 + 动作变换 | 真正深度遮挡、灯光和后期特效才用 Three.js |
| 流程、公式和复杂排版 | Canvas/SVG/DOM | 现成网页布局可 DOM + 暂停的 GSAP 时间轴 |
| 真正三维模型和材质 | Three.js / WebGL | 明确相机和资产，不把 2D 投影称作真实 3D |
| 已有 React 视频与复杂多轨 | Remotion 可作宿主 | 采用其帧时钟和实际导出命令，不嵌套独立时钟 |

### 起步实现的范围

新模板的 `visual` 是主体、风格、动作/效果、技术的独立字段，详见制作契约。它实作同一个种子角色在 flat/sand/particles 三种画法下的 sway/hop 动作，以及 none/reveal/assemble 效果。几何、表情和采样点复用；这些值只是可运行的起步范围，不是所有剧本必须使用的分类或角色。

执行者按内容改写主体/动作/材质实现。新增对象不凭改一个字符串就宣称支持。旧 `kind` 仅供已有示例配置兼容；新片不用它在角色与风格之间二选一。

## 复现常见效果

**卡通叙事**：把头、身体、肢体、眼口和道具定义在角色局部坐标系，统一 `drawCharacter(pose)`。位置用时间插值，起跳用曲线，落地压缩与回弹用局部时段。一个角色在各镜共享 rig，不逐镜重新画脸。影子随高度缩放；动作先做预备、执行、缓冲，再加装饰。

**沙画**：先把完整轮廓/场景画在离屏层，再用随时间变化的擦除/显露 mask 合成。砂粒位置、大小、亮度由 seed 和粒子索引固定；只改变揭示进度。背景纸纹和细粒缓存一次，不能每帧重新随机制造闪烁。笔迹沿路径逐段显露，细节密度分层；轮廓清楚比随机点数量更重要。角色转沙画时复用原轮廓。

**粒子**：把目标轮廓、文字或图形采样成固定目标点；建立固定粒子到目标点的映射。`position = lerp(source[i], target[i], ease(progress)) + boundedNoise(i,t)`。不每帧重新配对最近点。球体可用球面采样后旋转投影；透视近大远小、后侧更暗，不必因此引入 3D 库。密度、粒径和亮度留出字幕安全区。

**字效/图解**：让文字进入和对象变化对应因果。中文用已加载字体测量字宽，换行到安全区域。不要把透明度淡入加停留当作每个镜头唯一动作。数字滚动、路径描边、物体状态变化和对比可降低解说负担。

**混合转场**：用同一形状、位置、运动方向或颜色接镜，例如角色轮廓成为沙画，再从沙粒升起为粒子。不同画法共用 frame；不要让每个库自己跑 `requestAnimationFrame`。

## 帧契约适配

- p5.js：`noLoop()`；在初始化设置 `randomSeed/noiseSeed` 并预生成点集；`renderFrame(f)` 直接以 `f/fps` 计算并绘制，或设定目标帧后 `redraw()` 并等待完成。控制画布尺寸、像素密度，禁止隐藏的绘制状态随帧累积。
- DOM/SVG + GSAP：时间轴暂停，显式 `timeline.seek(f/fps)`，等待样式提交；禁用其他自动 CSS 动画。用真实舞台尺寸的容器作为 `#stage`，控件放在舞台外。
- Three.js/PixiJS：停止默认 ticker，在帧函数中设置所有对象/相机并执行 render。等待贴图/模型加载，锁定随机源；跨机器 GPU 输出不保证逐字节一致，一致性检查针对同一次环境。
- Remotion：采用其 `useCurrentFrame` 和视频配置作为时间来源，可把这里的编译时间轴导入它。使用 Remotion 的实际导出命令与检查；本 skill 自带 `render.cjs` 的验证结果不能替代另一渲染器的实测。

物理模拟或不可直接求某时刻的系统先按固定步长预演并缓存状态，或改成解析轨迹。需要随机跳帧仍能得到同一画面，不能“顺序播放看起来没问题”就宣称可离线导出。

## 可用性边界

只凭参考视频能判断视觉结构与可能算法，不能确认其源码、模型、依赖库或制作耗时。遇到真人表演、复杂电影镜头等程序绘制成本很高的内容，说明能用素材合成还是需换生成式视频路线；不要许诺一套简单 Canvas 模板覆盖所有视频。

## 官方 API 入口

- p5 的循环控制见 [noLoop](https://p5js.org/reference/p5/noLoop/)，固定随机序列见 [randomSeed](https://p5js.org/reference/p5/randomSeed/)。
- GSAP 的定位与暂停见 [Timeline](https://gsap.com/docs/v3/GSAP/Timeline/)。
- Three.js 的显式渲染和循环接口见 [WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)。
- Remotion 的帧语义见 [useCurrentFrame 源码](https://github.com/remotion-dev/remotion/blob/main/packages/core/src/use-current-frame.ts) 与 [时间偏移规则](https://www.remotion.dev/docs/timing)。
