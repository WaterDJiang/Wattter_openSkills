## 二、跑通的路径

### 权限前提
用户去「系统设置 → 隐私与安全性 → 屏幕录制」勾选宿主 App（实测 WorkBuddy）后，`screencapture -x -l <CGWindowID> -t png` 立即可用。

### 窗口与环境实测数据（2026-11-23，Mac）
- 微信文章窗口：`CGWindowID = 62565`，尺寸 817×1030
- 显示器布局：主屏 1728×1117 @ (0,0)，外接屏 2560×1080 @ (-436,-1080)，微信窗口在外接屏上，所以坐标有负值
- 留言面板滚动坐标：`[595.593, 551.218]`（在窗口内相对坐标）
- computer-use 的 `target_id = "62565"`、`view_id = "v1-62565"`

### 有效操作序列
1. `NSRunningApplication.activate` 激活微信 → 出现竖长文章窗口
2. computer-use `get_app_state` → `get_next_action` 定位右下角留言入口（坐标约 `[750, 1019]`）→ `click` 展开评论面板
3. computer-use `scroll`（坐标 `[595, 551]`，down 600px）
4. `screencapture -x -l 62565 -t png /tmp/screen_N.png`
5. Vision OCR 转文字
6. 重复 3–5 直到 md5 连续 3 屏不变

### 提速关键
- `view_id` 建立一次后可直接连续 scroll，无需每屏 get_app_state
- `get_next_action` 连续滚动几轮后会误判 `done`，此时**不带 task_id 重开新会话**，或干脆忽略它直接 scroll
- 41 屏的采集交给子代理批量跑，主对话只收最终统计

## 三、数据清洗经验

### 正文干扰识别
文章正文在左半屏，每屏都出现同一批句子（如「最后说GPT。」「想明白了这三个人的性格，我调度结构」）。用全局行频次识别：出现在 **≥12 屏** 的行判为正文干扰并剔除。实测 41 屏剔除 27 种正文行，OCR 从 2063 行降到 1075 行。

### 相邻屏重叠去重
scroll 600px 有重叠，用首尾滑窗匹配：若本屏开头 k 行 == 上屏结尾 k 行（k 最大 12），截掉这 k 行。

### 识别率现实
- 488 条显示留言 → 识别 251 条
- 原因：楼中折叠回复（「N条回复」）未展开；中后段点赞数 OCR 大量丢失；低赞/纯表情留言识别率低
- 报告里务必写清这个边界，不要声称「全量 488 条逐字」

## 五、分析结果模板要点

一份好的留言分析报告应包含：
1. **一句话结论**：先给最反直觉的发现（如「真正的主议题不是账号焦虑，而是怎么落地」）
2. **数据说明表**：采集路径、覆盖屏数、识别条数 vs 显示总数、精度边界
3. **议题分布**：6 类标签的条数 + 占比，最好配 Chart.js 横向条形图
4. **高赞 Top N**：昵称、赞数、摘要、议题标签
5. **核心洞察 3–5 条**：错位、争议、情感符号、赞数倒挂、新现象
6. **金句原文**：原样引用，标昵称
7. **选题与商机**：按优先级排序，商机给客单价 + 最小验证路径
8. **与前次修正**（如做过多次）：用对照表展示结论如何变化

## 六、合规提醒

分析「账号焦虑」「封号」「地区限制」这类议题是内容洞察，允许；但**不要**提供账号买卖、翻墙工具、中转站推荐的具体方案。用户若要求这类产出，明确拒绝并说明原因。

## 七、第二轮实战：微信 4.1 主窗口黑图坑与 Cmd+F 破局（2026-11-23）

第一次跑通时假设「微信窗口都能截图」。第二次用户只给公众号名「量子位」、没给链接，需要**自己**找到文章，这个假设崩溃了，浪费了大量轮次。以下结论按重要性排序。

### 7.1 根因：主窗口和独立窗口是两种东西

| 窗口类型 | 尺寸 | `kCGWindowSharingState` | 能否截图 / advisor 可见 |
|---|---|---|---|
| 微信**主窗口**（会话列表 / 公众号聚合页） | 935×790 或全屏 1728×1030 | **0** | ❌ 按 ID 截报错、整屏不渲染、advisor 黑图 |
| 「搜一搜」结果 / 公众号主页 / **文章**独立窗口 | 817×1030 | **1** | ✅ `screencapture -l` 完美，`image_base64_len ≈ 245KB` |
| 「设置」子窗口 | 640×560 | 1 | ✅ 可截（但不是采集目标） |

`sharing=0` 是微信 4.1 自己设的防截屏属性，**14:32 首次探测就是 0，不是操作改坏的**。别再试图修它。

### 7.2 判定窗口能否操作：`image_base64_len`

对候选窗口调 computer-use `get_app_state`，读返回里的 `image_base64_len`：

- **> 100 KB**（实测 245 KB）→ 画面完整可读，advisor 坐标可信
- **< 50 KB**（实测 24 KB / 49 KB）→ 纯黑图，advisor 在瞎猜，**禁止点击**

这是本 skill 最高性价比的判据。我在这上面栽了十几次：advisor 基于黑图给的三个坐标分别点到两篇无关文章，最后一次点击穿透到 Chrome。

### 7.3 焦点被抢：坐标点击的隐形杀手

即使把微信 `activate` 到前台（`frontmost=微信`），**每调用下一个工具（advisor / Bash）宿主 app 就立刻抢回焦点**，微信失前台后坐标点击就穿透。曾尝试：

- 数字窗口号 `"63826"` 作 `target_id` → 后台投递模式，不前置窗口 → 穿透
- `osascript` 单脚本内 `activate` + `System Events click` → 仍不可靠
- 后台 CGEvent 鼠标点击 → 无 Accessibility 权限，事件被丢弃

**结论：不要试图对主窗口做鼠标操作。** 改用键盘路径，并且把「激活 + 搜索 + 输入 + 回车」压进**同一个 Bash 脚本**，脚本内部用 `usleep` 等待，全程不跨工具调用。键盘 CGEvent（Cmd+F / Cmd+V / Return）对前台微信是有效的，实测成功。

### 7.4 破局路径（已跑通，优先记这条）

```
NSRunningApplication.activate(微信)
  → 同一脚本内：Cmd+F 唤起搜索面板（出现 368×432 浮层，id 每次变）
  → NSPasteboard 粘贴公众号名（中文不能靠 CGEvent 逐字打）
  → Return 打开第一项
  → 得到「搜一搜」结果独立窗口 817×1030，sharing=1
  → 之后全程 advisor 精确点击（画面完整可读）
```

完整可复用脚本见 `SKILL.md` 阶段 1 路径 B 的 B1。验证标志：搜索面板高度从 432 涨到 710 = 关键词命中；出现 817×1030 新窗口 = 成功进入搜一搜。

搜一搜窗口里：
1. 点「账号」卡片里的目标公众号（量子位卡片约 `(303, 300)`）→ 进公众号主页
2. 主页列表带每篇阅读量，**当天新推常只有一两千**（实测头条 4485、次条 2494），最新过万的是前一天一条 4.2万 → 必须逐条核对阅读量，别把「最新」当「过万」
3. 点目标文章 → 底部互动栏（赞 333 / 分享 2456 / 在看 68 / 留言 5）→ 点留言气泡展开面板

### 7.5 其他坑与处理

- **全屏尺寸锁死**：微信一旦进全屏（1728×1030），AX `setSize` 返回 0 但尺寸不变，`AXFullScreen=false` 也不生效。别跟它斗，等 `activate` 时微信可能自己恢复 935×790；不恢复也能用，全屏下布局不是等比缩放，**不要用用户截图的坐标按全屏尺寸换算**，会点错。
- **用户截图坐标换算**：视觉模型返回的图片常被缩放显示（实测 1866×1570 → 1122×944，系数 0.601），直接把显示坐标当原始像素会偏。若非用不可，先算 `缩放系数 = 显示宽 / 原图宽`，再除以 Retina 倍数 2 得逻辑坐标。
- **窗口漂到外接屏**：AX `setPosition` 可移回主屏（`result=0`），但全屏/换 Space 后会再漂。不要为了「摆整齐」反复移窗。
- **留言少时跳过 OCR**：一屏全显（≤10 条）时视觉直读比 OCR 准得多（实测 5/5 识别），省掉滚动+OCR+清洗全流程。报告里写清「未走 OCR」。

### 7.6 时间线复盘（哪一步该省掉）

| 阶段 | 实际发生 | 应该怎么做 |
|---|---|---|
| 前 1 小时 | 反复 hide 其他 app、移窗、raise、按 ID 截图 | 阶段 0 先测 `image_base64_len`，<50KB 立刻停手 |
| 中间 30 分钟 | 盲点黑图，开错文章，焦点穿透到 Chrome | 不点主窗口，直接走 B1 单脚本键盘路径 |
| 最后 5 分钟 | Cmd+F → 搜一搜窗口 → advisor 全程精确点击 → 5 分钟出报告 | **这才是正确起点** |

**一条经验**：用户说「先锁住页面再点」和「在左上角搜索栏搜」是对的，但执行上要理解成「锁前台 + 键盘搜索 + 独立窗口接管」，而不是「在黑图上点搜索栏」。
